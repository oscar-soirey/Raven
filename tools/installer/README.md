# Raven SDK Installer

One program per platform that installs the RavenGUI SDK and Raven Designer,
with nothing to download and nothing to install first. Its whole interface is
drawn by RavenGUI, from XML files embedded in it.

| Platform | What is distributed | Contents |
|---|---|---|
| Windows x64 | `RavenSDKInstaller.exe` | `msvc-static`, `msvc-shared`, `mingw-static`, `mingw-shared` packages, Raven Designer, templates |
| Linux x64 | `RavenSDKInstaller` | `gnu-static`, `gnu-shared` packages (GCC and Clang, glibc), Raven Designer, templates |
| macOS (arm64 + x86_64) | `RavenSDKInstaller.app` (zipped) | `apple-static`, `apple-shared` packages (universal), `Raven Designer.app` with MoltenVK, templates |

```sh
cmake -P tools/installer/package.cmake          # builds the packages, the installer, and packs: dist-installer/
```

## 1. RavenGUI as it is (what the installer builds on)

- **The library** is C11 (`src/`, `include/Raven.h`), one CMake project. It draws with
  Vulkan, loaded at run time (`vulkan-1.dll`, `libvulkan.so.1`, MoltenVK on macOS):
  nothing of Vulkan is linked. Platforms: Win32, X11 + Wayland, Cocoa, and a null
  (headless) platform used by the tests.
- **Packages**: `cmake --install` writes a CMake package (`include/`, `lib/`, `lib/cmake/raven`,
  `bin/`, `share/raven/` with the docs, licenses and all the bindings). `dist.bat` makes four
  of them on Windows (`msvc-static`, `msvc-shared`, `mingw-static`, `mingw-shared`); CI makes
  the Linux and macOS ones. The libraries of one compiler are not for another.
- **Bindings** (`bindings/`, generated by `tools/bindgen`): C++, Python, Rust, Go, C#, Zig,
  LuaJIT, Java, Odin, Bun, Node.js, C3. All but C++ load the *shared* library.
- **Raven Designer** (`tools/designer`, C) is one program with its fonts and splash screen
  embedded; it needs only the system and a Vulkan driver.
- **Useful API for an installer**: `Rfile_register_memory` (XML and images served from
  memory), `<Include>` in XML, `Rtask_post` (worker threads to the UI thread),
  `Rfile_dialog_select_folder`, `Rmessage_box`, the null backend and `Rwindow_capture`
  for tests and screenshots, and `raven.hpp` (C++).

## 2. Architecture

```
tools/installer/
  core/        the engine: payload (format, DEFLATE both ways, CRC), JSON, manifest, log,
               the installation transaction, uninstallation              (no system header)
  platform/    machine, folders, processes, permissions: platform_win32.cpp, platform_posix.cpp
  compilers/   detection of MSVC, MinGW-w64, GCC, Clang, Apple Clang
  shell/       integration: shortcuts, registration, context menus, uninstall entry
  templates/   project templates (files/), the engine that makes projects, raven-new,
               and raven_templates.h, the same thing for C programs (Raven Designer)
  ui/          the wizard (app.cpp) and the command line (cli.cpp); ui/xml: the interface
  pack/        raven_installer_pack: makes the payload and appends it to the program
  tests/       tests of the engine (ctest: installer_core)
  package.cmake  the whole chain, on each platform
```

The engine never touches the UI; the window and the command line call the same
functions. Everything platform-specific is in `platform/` and `shell/`.

### The payload

```
[ program ][ blob ][ blob ] ... [ index: deflated JSON ][ footer, 48 bytes ]
```

Appended to the executable on Windows and Linux (a single file), stored as
`Contents/Resources/payload.rvnpk` in the macOS bundle (so it can be signed).
A blob is the deflated content of one or several identical files (the headers
of the four Windows packages are stored once); each has a CRC-32 checked when
it is read. The index lists the files (with their symbolic links, on POSIX),
the packages, the templates, the designer. Paths that would leave the chosen
folders are refused when the payload is opened. The DEFLATE encoder and decoder
are part of the installer (no zlib); any zlib reads the streams (tested).

### The transaction

1. checks (absolute folders, write permission with a probe file, free space);
2. each file is written beside its place and renamed over it; what was there is
   moved into `<root>/.raven-txn` (this works on a program that is running on
   Windows) or, if it is a file of the user, kept beside it as `<name>.user-<date>`;
3. files of the previous version no longer selected are moved into `.raven-txn`
   (only if the user did not change them);
4. the maintenance program (`<SDK>/.raven-install/RavenSDKMaintenance`, this
   program without its payload), then the integrations;
5. the manifest: the point of no return. `.raven-txn` is deleted.

A failure or a cancel before 5 undoes everything in reverse order. Identical
files are not rewritten: running the same installation twice changes nothing
(repair puts back what was removed or changed). The manifest lists every file
with its size and CRC, every folder made, and for each integration what undoes
it; the uninstaller removes exactly that, and keeps any file whose CRC changed.

### Installed layout

```
<SDK>/                       default: %LOCALAPPDATA%\Programs\Raven\SDK, ~/.local/share/raven/sdk,
  msvc-static/ ...           ~/Library/Developer/Raven/SDK
  msvc-shared/ ...           each one a CMake package, as dist.bat makes them
  bin/raven-new[.exe]
  templates/
  .raven-install/            manifest.json, install.log, the maintenance program
<Designer>/                  %LOCALAPPDATA%\Programs\Raven\Designer, ~/.local/share/raven/designer,
  raven_designer[.exe]       /Applications/Raven Designer.app (or ~/Applications)
```

Nothing needs administrator rights. Run elevated (Windows) or as root (Linux),
the defaults become `Program Files` and `/opt/raven`, and the uninstall entry
goes to `HKEY_LOCAL_MACHINE`.

## 3. Platforms

| | Windows x64 | Linux x64 | macOS arm64 / x64 |
|---|---|---|---|
| Interface | Win32 + Vulkan | X11 or Wayland + Vulkan | Cocoa + MoltenVK (in the bundle) |
| No GPU driver / no display | message, then `--cli` | falls back to `--cli` | message |
| Compilers | MSVC (vswhere, toolset, Windows SDK, test build through vcvars64), MinGW-w64 (PATH, MSYS2, w64devkit, WinLibs, Chocolatey, Scoop) | GCC, Clang, versioned names | Apple Clang (only if `xcode-select -p` answers) |
| Packages | msvc-*, mingw-* | gnu-* | apple-* (universal) |
| Desktop shortcut | `.lnk` | `.desktop` (marked trusted for GNOME) | link on the Desktop |
| Menu | Start menu \ Raven | applications menu (`.desktop`) | Launchpad (the app is in Applications) |
| Registration | App Paths, Applications\raven_designer.exe | hicolor icon, `~/.local/bin/raven-designer` | `lsregister` |
| Open with Raven Designer | `Directory\shell` | Nautilus (Scripts sub-menu), Dolphin, Nemo | not offered |
| New Raven Project | `Directory\Background\shell`, a sub-menu | Nautilus (Scripts sub-menu), Dolphin (sub-menu), Nemo (one action per language) | not offered |
| Uninstall | Settings > Apps (`--uninstall`, quiet too) | "Raven SDK Maintenance" in the menu | the maintenance app in the SDK |

Windows 11 shows registry verbs in "Show more options": its first-level menu
only takes `IExplorerCommand` handlers of packaged (MSIX) applications.
macOS: Finder menus need a Finder Sync extension, which is an app extension
that must be signed; the installer says so instead of pretending.

## 4. Components reused, and what was added

Reused: the library and its CMake packages, `raven.hpp`, the XML loader with
`<Include>`, memory files, themes, the null backend and `Rwindow_capture`, the
designer as it is, the bindings and `examples/languages` (the templates follow it).

Added to RavenGUI itself (small, compatible):
- `vk_loader.c`: `RAVEN_VULKAN_LIBRARY` names the Vulkan library, and a macOS
  application finds MoltenVK in its own `Contents/Frameworks` (the installer
  and Raven Designer carry it);
- `RAVEN_BUILD_INSTALLER` (OFF by default) in the root `CMakeLists.txt`;
- an `installer` job in the CI, which packages, tests the engine, installs,
  builds a project made by `raven-new` and uninstalls, on the three systems.

## 5. Project templates

`templates/files/<id>/template.json` describes each one (see `templates/templates.hpp`).
The packer keeps a template only if the packages contain its binding, so the
menus offer what the SDK really has: C, C++, Python, Rust, C#, Java, Go, Zig,
Odin, LuaJIT, Bun. Each project has `main.xml` and `strings.csv` (the program
of `examples/languages`), the build files of its language with the paths of
the installed SDK, a `README.md`, and a `run.sh` / `run.bat` when the language
needs an environment. A right-click in an empty folder makes the project there;
in a folder with files, in a new folder `Raven<Language>App`. Nothing is ever
overwritten.

`raven-new` is the command behind the menus; `raven_templates.h` gives the same
templates to C programs, so that Raven Designer can offer "New project" from the
same files.

## 6. Building and testing

```sh
cmake -S . -B build -DRAVEN_BUILD_INSTALLER=ON -DRAVEN_BUILD_TESTS=ON
cmake --build build --target test_installer && ctest --test-dir build -R installer_core
cmake -P tools/installer/package.cmake            # the real installer, in dist-installer/
```

Windows: the installer program is built with the static C runtime
(`RAVEN_MSVC_STATIC_RUNTIME=ON`, done by `package.cmake`), so it needs no
redistributable. `-DFAMILIES=msvc` leaves MinGW-w64 out.

The program itself:

```
RavenSDKInstaller                      the wizard
RavenSDKInstaller --cli [--yes] [--sdk-dir D] [--designer-dir D] [--targets auto|all|a,b]
                  [--integrations default|all|none|a,b] [--no-sdk] [--no-designer] [--no-verify]
RavenSDKInstaller --uninstall [--quiet]
RavenSDKInstaller --list | --detect
RavenSDKInstaller --test-gui [--null] [--screenshots DIR]     walks the wizard by itself (tests)
```
