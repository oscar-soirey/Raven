# The Metal backend

This note describes the native Metal backend of Raven (issue #206): what it
is made of, how it maps the backend contract of `raven_backend.h` onto Metal,
and why each choice was made. It is written for whoever reads, reviews or
extends `src/render/metal/`.

On macOS and iOS Raven used to draw through Vulkan, which Apple systems only
have through MoltenVK and the Vulkan loader: two libraries to install, ship
and sign beside every application. The Metal backend draws the same frames
with what the system already has, and adds no dependency at all: no MoltenVK,
no Vulkan loader, no SPIRV-Cross, no Sokol, and no offline shader compiler.

The Vulkan backend stays. It is still compiled by default on Apple systems
and can be asked for with `R_BACKEND_VULKAN`; only the default changes.

## 1. Files

```
src/render/metal/
    metal_backend.h          state shared by the files below (Objective-C, private)
    metal_backend.m          the RBackendVTable, Init / Shutdown, WaitIdle, device loss, iOS suspension
    metal_pipeline.m         shader libraries, pipeline states, samplers, effects (CreateShader)
    metal_texture.m          textures and their uploads
    metal_frame.m            surfaces, RenderFrame, viewport callbacks, capture, glass (backdrop + blur)
    generate_shaders.py      embeds the .metal sources into generated/shaders.h
    shaders/
        common.metal         declarations shared by every library (structures, constants, sampler, helpers)
        ui.metal             the UI: vertex, fragment, and the fallback of the effects
        blur.metal           full-screen passes that build the backdrop of glass
        effect.metal         what Raven does around an effect (the MSL twin of raven_effect.glsl)
        effects/
            aurora.metal  shimmer.metal  neon.metal    ripple.metal
            plasma.metal  grain.metal    spotlight.metal  mesh.metal
    generated/
        shaders.h            written by generate_shaders.py; checked in, never edited by hand
```

Every `.m` file of the backend is compiled with ARC (`-fobjc-arc`), like
`uikit_platform.m`. The rest of Raven stays C; `metal_backend.h` is only
included by the files of this folder.

### Shaders are compiled at run time

The shaders are written in the Metal Shading Language (MSL) and compiled when
the backend starts, with `-[MTLDevice newLibraryWithSource:options:error:]`.
The offline compiler (`xcrun metal`) only comes with the full Xcode, not with
the Command Line Tools: requiring it would add a build dependency, which is
what this backend exists to remove. Compiling from source costs a few tens of
milliseconds at start (the UI and blur libraries), and a few more the first
time each built-in effect is used.

The sources stay readable in `shaders/*.metal`. `generate_shaders.py` turns
each one into a C string in `generated/shaders.h`, the way
`src/render/webgl/generate_shaders.py` does for WebGL, and the generated
header is checked in like `src/render/vulkan/generated/`.

### generated/shaders.h

The header defines exactly these symbols, one string per source file, and
nothing else:

| `rvn_mtl_effect_source` | `shaders/effect.metal` |
| `rvn_mtl_effect_aurora_source` | `shaders/effects/aurora.metal` |
| `rvn_mtl_effect_shimmer_source` | `shaders/effects/shimmer.metal` |
| `rvn_mtl_effect_neon_source` | `shaders/effects/neon.metal` |
| `rvn_mtl_effect_ripple_source` | `shaders/effects/ripple.metal` |
| `rvn_mtl_effect_plasma_source` | `shaders/effects/plasma.metal` |

```c
/* Generated by generate_shaders.py from src/render/metal/shaders; do not edit. */
#ifndef RVN_MTL_SHADERS_H
#define RVN_MTL_SHADERS_H

static const char rvn_mtl_common_source[] =
"#include <metal_stdlib>\n"
"...";
/* ... one array per file, in the order of the table ... */

#define RVN_MTL_EFFECT_COUNT 8
/* in the order of REffect: aurora, shimmer, neon, ripple, plasma, grain, spotlight, mesh */
static const char* const rvn_mtl_effect_sources[RVN_MTL_EFFECT_COUNT] = {
	rvn_mtl_effect_aurora_source,
	/* ... */
	rvn_mtl_effect_mesh_source
};

#endif
```

Each string is the file as it is (comments kept), one JSON-escaped line per
source line, LF line endings, so that the output does not depend on the
machine that runs the script. The strings are longer than the 4095
characters that `-Wpedantic` accepts in a literal: the `.m` files of the
backend are compiled with `-Wno-overlength-strings`, as the Emscripten build
already is.

`generate_shaders.py`:

- `python3 src/render/metal/generate_shaders.py` writes the header;
- `--check` writes nothing and exits with 1 when the header is not what the
  sources give (a test runs it, like `gen_wayland.py --check`);
- a missing source file is an error, unless `--allow-missing` is given, in
  which case its string is empty (only useful while the effects are being
  written: the backend then reports that the effect does not compile and
  draws it as a rounded rectangle).

### How the libraries are put together

The backend concatenates the strings before compiling them; only
`common.metal` includes `<metal_stdlib>` and says `using namespace metal;`.

| Library | Source | Made |
|---|---|---|
| UI | common + ui | at Init |
| blur | common + blur | at Init |
| effect *n* | common + effect + effects/*n* | at the first CreateShader that names effect *n* (then kept until Shutdown) |

A pipeline may take its vertex function from one library and its fragment
function from another: every effect pipeline uses `rvn_ui_vertex` from the UI
library. That works because both libraries declare the same varyings
structure (from `common.metal`) with explicit `[[user(...)]]` names.

The compile options are the same for every library: precise math
(`options.mathMode = MTLMathModeSafe` where available, else
`options.fastMathEnabled = NO`, the deprecated property being set under a
`#pragma clang diagnostic ignored "-Wdeprecated-declarations"`). Fast math
would change the hashes built on `fract(sin(x) * 43758.5453)` (grain, stars,
dithering) and the results of the effects compared with Vulkan.

## 2. The shaders: interface shared by the shaders and the backend

The MSL sources are ports of the GLSL of the Vulkan backend, line by line:

| MSL | ported from |
|---|---|
| `ui.metal` | `src/render/vulkan/shaders/ui.vert` + `ui.frag` |
| `blur.metal` | `src/render/vulkan/shaders/blur.vert` + `blur.frag` |
| `effect.metal` | `include/raven/shaders/raven_effect.glsl` |
| `effects/<name>.metal` | `src/render/vulkan/shaders/effects/<name>.frag` |

The GLSL stays the reference: the comments are kept, the names of the local
variables too, so that a change to one can be carried to the other by
reading them side by side.

### 2.1 Declarations of common.metal

Everything below is declared once, in `common.metal`, with exactly these names
and layouts. The backend mirrors the numbers in `metal_backend.h`.

```metal
#include <metal_stdlib>
using namespace metal;

/* primitive kinds (raven_backend.h) */
constant uint RVN_PRIM_RECT     = 0u;
constant uint RVN_PRIM_GLYPH    = 1u;
constant uint RVN_PRIM_SHADOW   = 2u;
constant uint RVN_PRIM_LINE     = 3u;
constant uint RVN_PRIM_TRIANGLE = 4u;
constant uint RVN_PRIM_GLASS    = 5u;
constant uint RVN_PRIM_BLUR     = 6u;
constant uint RVN_PRIM_CURVE    = 7u;
constant uint RVN_PRIM_SHADER   = 8u;
constant uint RVN_PRIM_MASK     = 15u;
constant uint RVN_FLAG_TEXTURED   = 16u;   /* R_INSTANCE_TEXTURED */
constant uint RVN_FLAG_NO_POINTER = 32u;   /* R_INSTANCE_NO_POINTER */

/*
 * One RDrawInstance, byte for byte (80 bytes, see raven_backend.h):
 *   offset  0  rect          float[4]
 *   offset 16  uv            float[4]
 *   offset 32  clip          float[4]
 *   offset 48  radii         float[4]
 *   offset 64  color         uint32_t, bytes R, G, B, A in memory order, straight alpha
 *   offset 68  border_color  uint32_t, the same
 *   offset 72  border_width  float
 *   offset 76  flags         uint32_t
 * The instances are read from a device buffer (not through a vertex
 * descriptor): the four float4 are 16-byte aligned because 80 is a multiple
 * of 16 and the buffer is bound at a multiple of 80.
 */
struct RvnInstance {
	float4 rect;
	float4 uv;
	float4 clip;
	float4 radii;
	uint color;
	uint border_color;
	float border_width;
	uint flags;
};
static_assert(sizeof(RvnInstance) == 80, "RvnInstance must match RDrawInstance");

/*
 * The push constants of the Vulkan UI pipeline (vec2 scale, translate,
 * pointer, unused), set with setVertexBytes. Metal's clip space points up,
 * so scale.y is negative here and the size of the frame, which ui.vert took
 * from scale, is given in the last member instead of `unused`:
 *   scale     = (2 / width, -2 / height)
 *   translate = (-1, 1)
 *   pointer   = RDrawData::pointer, in framebuffer pixels
 *   inv_size  = (1 / width, 1 / height)
 * width and height are those of the render target (the drawable). There is
 * no time here: the time of an effect travels in RDrawInstance::border_width,
 * as with Vulkan.
 */
struct RvnUniforms {
	float2 scale;
	float2 translate;
	float2 pointer;
	float2 inv_size;
};

/*
 * What rvn_ui_vertex hands to the fragment functions: the outputs of
 * ui.vert, location by location. The same structure is the stage_in of
 * rvn_ui_fragment, rvn_shader_fallback_fragment and rvn_effect_fragment.
 */
struct RvnVaryings {
	float4 position     [[position]];
	float2 uv           [[user(rvn_uv)]];                  /* location 0, interpolated */
	float4 rect         [[user(rvn_rect), flat]];          /* location 1 */
	float4 clip         [[user(rvn_clip), flat]];          /* location 2 */
	float4 radii        [[user(rvn_radii), flat]];         /* location 3 */
	float4 color        [[user(rvn_color), flat]];         /* location 4, premultiplied */
	float4 border_color [[user(rvn_border_color), flat]];  /* location 5, premultiplied */
	float  border_width [[user(rvn_border_width), flat]];  /* location 6 (the time of an effect) */
	uint   flags        [[user(rvn_flags), flat]];         /* location 7 */
	float4 params       [[user(rvn_params), flat]];        /* location 8: the uv of the instance as they are */
	float2 inv_size     [[user(rvn_inv_size), flat]];      /* location 9: 1 / size of the target */
	float4 pointer      [[user(rvn_pointer), flat]];       /* location 10: pointer (pixels), hover, press */
};

/* blur.frag's push constants, set with setFragmentBytes (16 bytes) */
struct RvnBlurUniforms {
	float2 step;   /* size of a texel of the source, times the spread of the filter */
	int mode;      /* 0 reduce, 1 enlarge, 2 copy */
	int pad;
};

struct RvnBlurVaryings {
	float4 position [[position]];
	float2 uv       [[user(rvn_blur_uv)]];
};

/* the sampler of every backdrop read and of the blur passes: the sampler_linear of the Vulkan backend */
constexpr sampler rvn_linear(coord::normalized, address::clamp_to_edge, filter::linear, mip_filter::none);

/* GLSL's mod (x - y * floor(x / y)); MSL's fmod truncates and differs for negative values */
inline float  rvn_mod(float x, float y)   { return x - y * floor(x / y); }
inline float2 rvn_mod(float2 x, float2 y) { return x - y * floor(x / y); }
inline float3 rvn_mod(float3 x, float3 y) { return x - y * floor(x / y); }

/* Rounded box centered on the origin; radii = top-left, top-right, bottom-right, bottom-left (ui.frag's sd_round_box). */
float rvn_sd_round_box(float2 p, float2 half_size, float4 radii);
```

`rvn_sd_round_box` is defined in `common.metal` (it is used by the UI, the
fallback and the effects). The other helpers of `ui.frag` (`sd_segment`,
`sd_triangle`, `sd_round_box_normal`, `dispersed`, `glass`, `blur`, `grain`)
live in `ui.metal`; they take the textures they read as parameters
(`texture2d<float>`), since MSL functions cannot see the bindings of the
entry point.

### 2.2 Bindings

| Stage | Index | Content |
|---|---|---|
| vertex, UI and effects | `buffer(0)` | the instance buffer of the frame, bound at `first_instance * 80` with `setVertexBufferOffset` |
| vertex, UI and effects | `buffer(1)` | `RvnUniforms` (`setVertexBytes`, 32 bytes) |
| fragment, UI and effects | `texture(0)` | the texture of the command (`RDrawCommand::texture`), or a 1 x 1 white texture |
| fragment, UI and effects | `sampler(0)` | the sampler of that texture: nearest, linear or trilinear (its `RFilterType`) |
| fragment, UI and effects | `texture(1)` | sharp backdrop (half size), or the white texture when the frame has no glass |
| fragment, UI and effects | `texture(2)` | blurred backdrop (half size), or the white texture |
| fragment, blur | `texture(0)` | the source of the pass |
| fragment, blur | `buffer(0)` | `RvnBlurUniforms` (`setFragmentBytes`, 16 bytes) |

The backdrop textures and the blur passes are read with the constant sampler
`rvn_linear`, so the backend binds no sampler for them.

In `metal_backend.h`:

```c
#define RVN_MTL_BUFFER_INSTANCES        0
#define RVN_MTL_BUFFER_UNIFORMS         1
#define RVN_MTL_TEXTURE_UI              0
#define RVN_MTL_SAMPLER_UI              0
#define RVN_MTL_TEXTURE_BACKDROP        1
#define RVN_MTL_TEXTURE_BACKDROP_BLUR   2
#define RVN_MTL_BLUR_TEXTURE_SOURCE     0
#define RVN_MTL_BLUR_BUFFER_UNIFORMS    0
```

### 2.3 Functions

| Library | Function | Signature |
|---|---|---|
| UI | `rvn_ui_vertex` | `vertex RvnVaryings rvn_ui_vertex(uint vid [[vertex_id]], uint iid [[instance_id]], const device RvnInstance* instances [[buffer(0)]], constant RvnUniforms& u [[buffer(1)]])` |
| UI | `rvn_ui_fragment` | `fragment float4 rvn_ui_fragment(RvnVaryings in [[stage_in]], texture2d<float> u_texture [[texture(0)]], sampler u_sampler [[sampler(0)]], texture2d<float> u_backdrop [[texture(1)]], texture2d<float> u_backdrop_blur [[texture(2)]])` |
| UI | `rvn_shader_fallback_fragment` | `fragment float4 rvn_shader_fallback_fragment(RvnVaryings in [[stage_in]])` |
| blur | `rvn_blur_vertex` | `vertex RvnBlurVaryings rvn_blur_vertex(uint vid [[vertex_id]])` |
| blur | `rvn_blur_fragment` | `fragment float4 rvn_blur_fragment(RvnBlurVaryings in [[stage_in]], texture2d<float> source [[texture(0)]], constant RvnBlurUniforms& u [[buffer(0)]])` |
| effect *n* | `rvn_effect_fragment` | `fragment float4 rvn_effect_fragment(RvnVaryings in [[stage_in]], texture2d<float> rvn_texture [[texture(0)]], sampler rvn_texture_sampler [[sampler(0)]], texture2d<float> rvn_backdrop [[texture(1)]], texture2d<float> rvn_backdrop_blur [[texture(2)]])` |

There is no separate erase function: R_DRAW_ERASE draws with `rvn_ui_vertex`
and `rvn_ui_fragment` and only the blending differs, as in Vulkan.

`rvn_ui_vertex` is `ui.vert` with:

- `RvnInstance inst = instances[iid];` in place of the vertex attributes;
  colors unpacked with `unpack_unorm4x8_to_float(inst.color)`, which reads the
  byte at the lowest address as `x` (R): the `VK_FORMAT_R8G8B8A8_UNORM`
  attribute of Vulkan;
- `gl_VertexIndex` replaced by `vid` (four vertices, triangle strip);
- `out.inv_size = u.inv_size;` in place of `pc.scale * 0.5`;
- `out.position = float4(position * u.scale + u.translate, 0.0, 1.0);`.

`instance_id` counts from 0 in every draw: the backend never draws with a base
instance, it moves the buffer offset instead (see 5.4). The quad expansion of
each primitive kind is copied as it is.

`rvn_ui_fragment` is `ui.frag` with `p = in.position.xy`. It returns the
premultiplied color, as `ui.frag` does; `R_PRIM_SHADER` is not one of its
branches (that kind only reaches it in the fallback case below, which uses
its own function).

`rvn_shader_fallback_fragment` is what the contract allows a backend without
a given effect to draw: the rounded rectangle of the instance filled with its
color. Same clip test and coverage as the RECT branch of `ui.frag`, no
outline, times the opacity of bits 8..15 of `flags`:

```metal
fragment float4 rvn_shader_fallback_fragment(RvnVaryings in [[stage_in]]) {
	float2 p = in.position.xy;
	if (p.x < in.clip.x || p.y < in.clip.y || p.x >= in.clip.z || p.y >= in.clip.w) {
		discard_fragment();
		return float4(0.0);
	}
	float2 half_size = (in.rect.zw - in.rect.xy) * 0.5;
	float d = rvn_sd_round_box(p - (in.rect.xy + half_size), half_size, in.radii);
	float coverage = clamp(0.5 - d, 0.0, 1.0);
	float opacity = float((in.flags >> 8) & 255u) / 255.0;
	return in.color * (coverage * opacity);
}
```

`rvn_blur_vertex` makes the full-screen triangle of `blur.vert`, turned for
Metal's clip space:

```metal
float2 corner = float2(float((vid << 1) & 2u), float(vid & 2u));
out.uv = corner;                                                       /* (0, 0) = top left of the source */
out.position = float4(corner.x * 2.0 - 1.0, 1.0 - corner.y * 2.0, 0.0, 1.0);
```

`rvn_blur_fragment` is `blur.frag`, its three modes unchanged, every read
being `source.sample(rvn_linear, uv, level(0.0))`.

### 2.4 Coordinate systems

| | Vulkan | Metal |
|---|---|---|
| clip space, y | points down (y = -1 is the top) | points up (y = +1 is the top) |
| framebuffer / viewport origin | top left | top left |
| `gl_FragCoord.xy` / `[[position]].xy` | pixels from the top left, centers at .5 | the same |
| texture coordinates | (0, 0) = first texel of the first row uploaded | the same |
| derivatives along y | toward the bottom | toward the bottom |

So the only flip is in clip space, and it is entirely in the uniforms
(`scale.y < 0`, `translate.y = 1`) and in `rvn_blur_vertex`. Nothing reads the
backdrop upside down (unlike WebGL, whose framebuffers are bottom-up).
`p = in.position.xy` is exactly Vulkan's `gl_FragCoord.xy`, so every distance,
clip test and backdrop coordinate of the shaders stays as it is.

### 2.5 GLSL to MSL, sample for sample

| GLSL | MSL |
|---|---|
| `vec2/3/4`, `uvec`, `mat2(a, b, c, d)` | `float2/3/4`, `uint2`, `float2x2(float2(a, b), float2(c, d))` (both column-major) |
| `const T X = ...;` at file scope, arrays `T[n](...)` | `constant T X = ...;`, `constant float3 SPECTRUM[7] = { ... };` |
| `out vec2 normal` (parameter) | `thread float2& normal` |
| `texture(t, uv)` | `t.sample(s, uv)` |
| `textureLod(t, uv, 0.0)` | `t.sample(s, uv, level(0.0))` |
| `textureGrad(t, uv, dx, dy)` | `t.sample(s, uv, gradient2d(dx, dy))` |
| `dFdx`, `dFdy`, `fwidth` | `dfdx`, `dfdy`, `fwidth` |
| `atan(y, x)` | `atan2(y, x)` (`atan(x)` with one argument is the same) |
| `mod(x, y)` | `rvn_mod(x, y)` (never `fmod`) |
| `inversesqrt` | `rsqrt` |
| `radians(deg)` | `deg * (RAVEN_PI / 180.0)` (MSL has no `radians`; grain, shimmer) |
| `discard;` | `discard_fragment(); return float4(0.0);` |
| `gl_FragCoord.xy` | `in.position.xy` |

- The derivatives of `ui.frag` (`uv_dx`, `uv_dy`) are taken first, before the
  clip test and the branches, exactly where they are in GLSL: derivatives are
  only defined while all four pixels of a quad run, in Metal as in Vulkan.
- `textureGrad` with the same gradients picks the same mip level as Vulkan's
  (trilinear sampler, 5.3); on the textures without mipmaps it reads level 0.
- Vector built-ins given a scalar (`max(q, 0.0)`, `clamp(c, 0.0, 1.0)`,
  `mix(a, b, 0.5)` on vectors) are accepted as in GLSL and need no change.
- Math is precise (1, "How the libraries are put together"); `sin`, `exp`,
  `pow` then agree with Vulkan drivers to the last bits that matter for
  8-bit output.

### 2.6 What Raven does around an effect (effect.metal)

`effect.metal` is `raven_effect.glsl` in MSL: the structure an effect
receives, the helpers it may use, and the fragment function that calls it.

```metal
struct RavenEffect {
	float2 uv;       /* (0, 0) top left .. (1, 1) bottom right of the rectangle */
	float2 pixel;    /* the same in pixels */
	float2 size;     /* size of the rectangle, pixels */
	float2 screen;   /* position in the window, pixels (for raven_backdrop) */
	float edge;      /* distance to the edge, negative inside */
	float time;      /* seconds */
	float2 pointer;  /* pixels from the top left of the rectangle; below -1e5 when unknown */
	float hover;     /* 0..1 */
	float press;     /* 0..1 */
	float4 color;    /* straight alpha */
	float4 color2;   /* straight alpha */
	float4 params;
};

/* MSL functions cannot see the bindings of the entry point: they are passed to raven_effect */
#define RAVEN_EFFECT_ARGS RavenEffect fx, texture2d<float> rvn_texture, sampler rvn_texture_sampler, \
	texture2d<float> rvn_backdrop, texture2d<float> rvn_backdrop_blur, float2 rvn_inv_size

#define raven_texture(uv)           rvn_texture.sample(rvn_texture_sampler, (uv))
#define raven_backdrop(screen)      rvn_backdrop.sample(rvn_linear, (screen) * rvn_inv_size, level(0.0))
#define raven_backdrop_blur(screen) rvn_backdrop_blur.sample(rvn_linear, (screen) * rvn_inv_size, level(0.0))

constant float RAVEN_PI = 3.14159265358979;
constant float RAVEN_TAU = 6.28318530717959;

float  raven_hash(float2 p);
float  raven_noise(float2 p);
float  raven_fbm(float2 p);
float3 raven_hsv(float3 c);           /* uses rvn_mod for GLSL's mod */
bool   raven_has_pointer(RavenEffect fx);
float  raven_sd_round_box(float2 p, float2 half_size, float4 radii);   /* = rvn_sd_round_box */

/* the effect, defined by the file of the effect that follows this one */
float4 raven_effect(RAVEN_EFFECT_ARGS);
```

The helpers are defined in `effect.metal` with the bodies of
`raven_effect.glsl`. An effect file then contains only its function:

```metal
/* Spotlight: ... (the comment of the GLSL file, kept) */
float4 raven_effect(RAVEN_EFFECT_ARGS) {
	float2 at = float2(fx.params.x, fx.params.y) * fx.size;
	...
}
```

`rvn_effect_fragment` is the `main()` of `raven_effect.glsl`:

```metal
fragment float4 rvn_effect_fragment(RvnVaryings in [[stage_in]],
	texture2d<float> rvn_texture [[texture(0)]], sampler rvn_texture_sampler [[sampler(0)]],
	texture2d<float> rvn_backdrop [[texture(1)]], texture2d<float> rvn_backdrop_blur [[texture(2)]]) {
	float2 p = in.position.xy;
	if (p.x < in.clip.x || p.y < in.clip.y || p.x >= in.clip.z || p.y >= in.clip.w) {
		discard_fragment();
		return float4(0.0);
	}
	float2 size = max(in.rect.zw - in.rect.xy, float2(1.0));
	float2 center = (in.rect.xy + in.rect.zw) * 0.5;
	float d = rvn_sd_round_box(p - center, size * 0.5, in.radii);
	float coverage = clamp(0.5 - d, 0.0, 1.0);
	if (coverage <= 0.0) {
		discard_fragment();
		return float4(0.0);
	}
	RavenEffect fx;
	fx.pixel = p - in.rect.xy;
	fx.uv = fx.pixel / size;
	fx.size = size;
	fx.screen = p;
	fx.edge = d;
	fx.time = in.border_width;
	fx.pointer = in.pointer.xy - in.rect.xy;
	fx.hover = in.pointer.z;
	fx.press = in.pointer.w;
	/* (the vertex function premultiplies the colors: the effect gets them straight) */
	fx.color = in.color.a > 0.0 ? float4(in.color.rgb / in.color.a, in.color.a) : float4(0.0);
	fx.color2 = in.border_color.a > 0.0 ? float4(in.border_color.rgb / in.border_color.a, in.border_color.a) : float4(0.0);
	fx.params = in.params;

	float4 color = raven_effect(fx, rvn_texture, rvn_texture_sampler, rvn_backdrop, rvn_backdrop_blur, in.inv_size);
	color = clamp(color, float4(0.0), float4(1.0));
	float opacity = float((in.flags >> 8) & 255u) / 255.0;
	return float4(color.rgb * color.a, color.a) * (coverage * opacity);
}
```

The pointer, hover and press come from `rvn_ui_vertex` exactly as from
`ui.vert`: `in.pointer` is `(-1e6, -1e6, 0, 0)` when the instance has
`R_INSTANCE_NO_POINTER`, else `(u.pointer, hover, press)` with hover = bits
16..23 and press = bits 24..31 of `flags`, over 255.

## 3. Pipeline states, formats and textures

### 3.1 Pixel format and color space

Every render target of the backend is `MTLPixelFormatBGRA8Unorm`: the
drawables of the layers, the backdrop images, the headless targets. That is
the format the Vulkan backend picks first (`VK_FORMAT_B8G8R8A8_UNORM` with
`VK_COLOR_SPACE_SRGB_NONLINEAR_KHR`, see `rvn_vk_choose_format`): UI colors
are sRGB values blended as they are, with no conversion on write. An `_sRGB`
format would blend in linear light and change every anti-aliased edge and
every translucent color.

The layer is tagged sRGB (`layer.colorspace = CGColorSpaceCreateWithName(kCGColorSpaceSRGB)`,
released after), which is what MoltenVK does for `SRGB_NONLINEAR`: the window
server then shows the same colors with both backends, on a wide-gamut screen
too. The property exists from macOS 10.11 and iOS 16; on older iOS it is
skipped (`@available`), iOS treating untagged content as sRGB anyway.

Because the format is fixed, the pipeline states are made once, at Init.

### 3.2 Pipeline states

| Pipeline | Vertex | Fragment | Blending (color and alpha alike) |
|---|---|---|---|
| UI | `rvn_ui_vertex` | `rvn_ui_fragment` | on: source ONE, destination ONE_MINUS_SOURCE_ALPHA, ADD |
| erase | `rvn_ui_vertex` | `rvn_ui_fragment` | on: source ZERO, destination ONE_MINUS_SOURCE_ALPHA, ADD |
| fallback | `rvn_ui_vertex` | `rvn_shader_fallback_fragment` | as UI |
| effect *n* | `rvn_ui_vertex` (UI library) | `rvn_effect_fragment` (effect library *n*) | as UI |
| blur | `rvn_blur_vertex` | `rvn_blur_fragment` | off |

All: one color attachment `BGRA8Unorm`, write mask all, no depth or stencil,
sample count 1, no culling (Metal's default), triangle strip of 4 vertices
for the instanced ones, 3 vertices (triangle) for blur. The colors leave the
fragment functions premultiplied, so the UI blending is the premultiplied
"over"; erase is the blend the contract gives for R_DRAW_ERASE.

### 3.3 Samplers

Three `MTLSamplerState`, made at Init, all clamp to edge on S and T,
normalized coordinates, anisotropy 1, the twins of the Vulkan samplers:

| Sampler | min / mag | mip filter | Used for |
|---|---|---|---|
| nearest | nearest | not mipmapped | `R_FILTER_NEAREST` |
| linear | linear | not mipmapped | `R_FILTER_LINEAR`, and `R_FILTER_MIPMAP` textures that have one level |
| trilinear | linear | linear | `R_FILTER_MIPMAP` textures with a mip chain |

### 3.4 Textures

- `R_TEXTURE_RGBA8` is `MTLPixelFormatRGBA8Unorm` (straight alpha, as
  given).
- `R_TEXTURE_ALPHA8` is `MTLPixelFormatR8Unorm` with the swizzle
  `(ONE, ONE, ONE, RED)` on the texture (`MTLTextureDescriptor.swizzle`):
  the shaders sample `(1, 1, 1, value)`, like the swizzled view of Vulkan,
  and need no branch. Should a device refuse a swizzled texture, the texture
  is made `RGBA8Unorm` instead and its uploads expanded to `(255, 255, 255,
  value)` on the CPU; the shaders do not change.
- Every texture is `MTLStorageModePrivate`, usage `ShaderRead`. Pixels reach
  it through a blit: they are copied into a new shared `MTLBuffer` and a
  `copyFromBuffer:...toTexture:` is encoded into the *upload command buffer*,
  which is committed before the next frame (or by WaitIdle). The queue runs
  command buffers in order, so a frame always sees the textures as they were
  when it was submitted, and a texture updated while a previous frame still
  reads it is never changed under that frame (writing a shared texture with
  `replaceRegion` would be). It also works on the iOS Simulator, where
  textures cannot be shared with the CPU.
- `R_FILTER_MIPMAP` gives an RGBA8 texture larger than 1 x 1 a full mip chain,
  filled with `generateMipmapsForTexture:` after each upload, the rule of
  `rvn_vk_wants_mipmaps`. A texture that switches to `R_FILTER_MIPMAP` without
  levels is made again with them (level 0 copied by a blit), as in
  `rvn_vk_texture_add_mipmaps`.
- The white 1 x 1 RGBA8 texture is bound where a command has no texture and
  as both backdrops of a frame without glass.
- DestroyTexture only drops the reference: a command buffer keeps alive what
  it uses until the GPU has finished with it, so nothing needs to wait.

Glyph pages are `R_TEXTURE_ALPHA8` today (color glyphs, COLR emoji, are
drawn as layers of outlines, each in its own color, through the same pages). Pages in color (emoji) would be
`R_TEXTURE_RGBA8` textures drawn by the same `R_PRIM_GLYPH` instances; the
backend already handles both formats for any primitive, so nothing in it
depends on the format the font code chooses.

## 4. Glass: the backdrop and its blur

The algorithm is the one of `vk_glass.c`, with one simplification that Metal
allows: the frame is drawn straight into the drawable, never into an
offscreen copy of it, because a Metal drawable can be sampled once its render
pass has ended.

1. The layer is made with `framebufferOnly = NO` (always, at CreateSurface):
   its drawables can then be sampled and blitted from. That also makes
   `Rwindow_capture` possible at any time.
2. The first time a frame contains `R_DRAW_BACKDROP`, the surface gets its
   backdrop images, all `BGRA8Unorm`, private, usage `RenderTarget |
   ShaderRead`:
   - `down[i]`, i = 0..2 (`RVN_MTL_BLUR_LEVELS` = 3): `width >> (i + 1)` x
     `height >> (i + 1)` (at least 1), the size of the drawable halved,
     quartered, divided by 8; `down[0]` is the sharp backdrop;
   - `up[i]`, i = 0..1: the sizes of `down[0]` and `down[1]`; `up[0]` is
     the blurred backdrop.
   They are made again when the drawable changes size, and `glass_filled`
   then starts at R_FALSE.
3. At each `R_DRAW_BACKDROP` of the frame:
   - `endEncoding` on the render encoder of the frame;
   - the passes of `rvn_vk_glass_capture`, with the same numbers: `spread =
     clamp(data->scale, 1, 3)`, `margin = 18 * spread + 20`, the same
     whole-or-part decision (part only once `glass_filled`, and when the area
     is under 80 % of the frame), the same area rounding
     (`rvn_vk_glass_area`), the same `step = spread * (mode == 0 ? 1 : 0.5) /
     source size` (spread 1 for the first reduction), in the same order:
     drawable -> `down[0]` -> `down[1]` -> `down[2]`, then `down[2]` ->
     `up[1]` -> `up[0]`. Each pass is one render command encoder on its
     target with the blur pipeline, the source at `texture(0)`, three vertices;
     a whole pass uses `MTLLoadActionDontCare`, a partial one
     `MTLLoadActionLoad` with the area as scissor rectangle; store action
     Store;
   - a new render encoder on the drawable with `MTLLoadActionLoad`, and the UI
     state bound again (5.3), the backdrops now `down[0]` and `up[0]`.
4. Metal tracks these textures (they are not in a heap and not untracked), so
   the passes see what the encoders before them wrote, without barriers.

`rvn_vk_glass_present_scene` (the copy of the offscreen frame to the
swapchain) has no counterpart: the frame already is in the drawable. The
result is the same pixels: that copy read pixel centers of an image of the
same size with a linear sampler.

A frame without `R_DRAW_BACKDROP` binds the white texture as both backdrops
and never touches the backdrop images, like the Vulkan path without glass.
If the images cannot be made, `R_DRAW_BACKDROP` is ignored and glass shows
white, as with Vulkan.

## 5. The frame

### 5.1 Surfaces

`CreateSurface(window, native, width, height)`:

| `native->system` | Target |
|---|---|
| `R_WINDOW_SYSTEM_COCOA`, `R_WINDOW_SYSTEM_UIKIT` | `native->window` is the `CAMetalLayer*` of the content view (`(__bridge CAMetalLayer*)(void*)native->window`, checked with `isKindOfClass:`) |
| `R_WINDOW_SYSTEM_NONE` (headless runs, the null platform) | an offscreen `BGRA8Unorm` texture of the framebuffer size, private, usage `RenderTarget \| ShaderRead`; frames are rendered and can be captured, nothing is presented |
| anything else | error (`rvn_error(R_ERROR_BACKEND, ...)`), R_FALSE |

The headless target is what lets `test_render` run on Metal without a window,
as it runs on Vulkan with `VK_EXT_headless_surface`.

On the layer, inside an explicit `[CATransaction begin]` / `[CATransaction
commit]` with actions disabled (the render thread has no run loop to commit
an implicit transaction):

```objc
layer.device = g_mtl.device;              /* the same device as the platform's MTLCreateSystemDefaultDevice() */
layer.pixelFormat = MTLPixelFormatBGRA8Unorm;
layer.framebufferOnly = NO;
layer.maximumDrawableCount = 3;
layer.colorspace = srgb;                  /* 3.1 */
layer.displaySyncEnabled = vsync;         /* macOS only */
layer.drawableSize = CGSizeMake(width, height);
```

`layer.opaque` and `layer.contentsScale` belong to the platform, which knows
whether the window is seen through and what its scale is; the backend does
not change them. A window that is seen through (`native->transparent`) has
`opaque = NO`, and the premultiplied alpha left in the drawable is what the
window server blends with: that is Vulkan's
`VK_COMPOSITE_ALPHA_PRE_MULTIPLIED_BIT_KHR`.

`DestroySurface` waits until the frames of that surface in flight are
finished (it takes and gives back every slot of its semaphore), then drops
the layer and the backdrop images.

### 5.2 One frame, step by step

`RenderFrame(data, capture)` runs on the render thread, entirely inside an
`@autoreleasepool` (the render thread has none of its own, and drawables are
autoreleased: without it they pile up and `nextDrawable` stalls). So does
every other function of the table that touches Metal objects.

1. `capture` is cleared. Nothing is drawn when the device is lost, when iOS
   suspended rendering (5.8), when the surface is unknown or the framebuffer
   is 0 x 0.
2. The upload command buffer, if any, is committed (what `rvn_vk_uploads_flush` does for Vulkan).
3. The size: when `layer.drawableSize` is not `framebuffer_width` x
   `framebuffer_height`, it is set (in a CATransaction). When `data->vsync`
   changed, `displaySyncEnabled` is set (macOS). Headless targets are made
   again at the new size.
4. Frame slot: `slot = cursor % RVN_MTL_FRAMES`, `RVN_MTL_FRAMES` = 3, and
   `dispatch_semaphore_wait(surface->slots, DISPATCH_TIME_FOREVER)`. The
   semaphore starts at 3 and is signaled by the completed handler of the
   command buffer of each frame: a slot is never written while the GPU reads
   it. The cursor moves on only once the frame is committed (step 9): a frame
   dropped on the way (no drawable, no command buffer, iOS suspended) signals
   the semaphore back and keeps its slot for the next frame, so the slots stay
   in step with the semaphore.
5. Instances: copied into the slot's buffer (`MTLResourceStorageModeShared |
   MTLResourceCPUCacheModeWriteCombined`), which grows like Vulkan's (at
   least 1024 instances, doubled until large enough; the slot is idle, so it
   can be replaced).
6. Drawable: `[layer nextDrawable]` (blocks at most one second,
   `allowsNextDrawableTimeout` left at YES). nil: the semaphore is signaled
   back and the frame is dropped; the next one tries again.
7. `commandBuffer = [queue commandBuffer]`, with a completed handler that
   signals the semaphore and looks at the status (5.7).
8. The render pass on the drawable texture: load action Clear with
   `data->clear_color` as given (no conversion, the target is UNORM), store
   action Store. Then the UI state (5.3) and the commands (5.4).
9. `endEncoding`; the capture blit when asked (5.6); `presentDrawable:` (not
   for headless targets); `commit`.
10. When capturing: `waitUntilCompleted`, then the pixels are converted.

### 5.3 The UI state

Bound at the start of the pass, after each backdrop capture and after each
viewport callback (the application may have changed anything):

- the UI pipeline state;
- the state Metal keeps in the encoder rather than in the pipeline state (in
  Vulkan it is part of the pipeline, so binding the UI pipeline restores it):
  cull mode none, fill mode fill, clockwise front faces, no depth bias, depth
  clip, blend color 0 and stencil reference 0. A viewport callback that culls
  or draws lines would otherwise hide the primitives drawn after it;
- the viewport `(0, 0, target width, target height, 0, 1)`;
- the scissor: the whole target. As with Vulkan, the clip of each primitive
  is applied by the fragment functions (`RDrawInstance::clip`), not by the
  scissor: commands do not each need their own;
- `buffer(0)` = instances of the slot, `buffer(1)` = `RvnUniforms` (2.1);
- `texture(1)`, `texture(2)` = the backdrops, or white;
- the texture and sampler of the command are bound by each draw.

### 5.4 Commands

| Command | Metal |
|---|---|
| `R_DRAW_INSTANCES` | texture + sampler of the command at index 0 (white + linear if none or not yet uploaded), then `setVertexBufferOffset:first_instance * 80 atIndex:0` and `drawPrimitives:MTLPrimitiveTypeTriangleStrip vertexStart:0 vertexCount:4 instanceCount:instance_count` |
| `R_DRAW_ERASE` | the same with the erase pipeline, then the UI pipeline again |
| `R_DRAW_SHADER` | the same with the pipeline of the shader (7), then the UI pipeline again |
| `R_DRAW_BACKDROP` | 4, when the frame has glass; ignored otherwise |
| `R_DRAW_CALLBACK` | 5.5 |

A command whose `first_instance + instance_count` exceeds
`data->instance_count`, or whose count is 0, is skipped, as in
`rvn_vk_record_commands`. The buffer offset replaces a base instance on
purpose: the Vulkan backend found that some GPUs (the iOS Simulator, "Apple
2" family) cannot draw with a non-zero base instance; no shader reads the
instance index other than to index the buffer from the offset.

### 5.5 Viewport callbacks

As in `rvn_vk_run_callback`: the clip of the command is intersected with the
target; an empty one, a missing callback or an empty rectangle draws nothing.
Otherwise the encoder gets the viewport `command->rect` and the scissor of the
clipped area, and the callback receives an `RViewportDrawInfo` with
`backend = R_BACKEND_METAL`, the rectangles and sizes filled as for Vulkan,
`color_format = MTLPixelFormatBGRA8Unorm`, `command_buffer` and `render_pass`
NULL, and three fields added at the end of the structure:

```c
	/** Metal: id<MTLRenderCommandEncoder> of the frame, inside its render pass (do not end it). */
	void* metal_encoder;
	/** Metal: id<MTLCommandBuffer> the encoder belongs to. */
	void* metal_command_buffer;
	/** Metal: id<MTLDevice> of the backend, to make pipeline states that match color_format. */
	void* metal_device;
```

They are `__bridge` casts: valid during the call only, not retained. The
Vulkan backend leaves them NULL (its `memset` already does). Appending them
keeps the layout of the existing fields: code built against the old header
reads the same members. `color_format` is documented as "Vulkan: VkFormat;
Metal: MTLPixelFormat". The application's pipeline must have one
`BGRA8Unorm` color attachment, no depth, one sample. After the call, the UI
state is bound again (5.3).

### 5.6 Capture

When `capture` is given: after the last render encoder, a blit encoder copies
the top-left `min(target, framebuffer)` pixels of the drawable (or headless
target) into a new shared buffer (`bytesPerRow = width * 4`). After
`waitUntilCompleted`, the pixels are converted as in `rvn_vk_finish_capture`:
B and R swapped (the target is BGRA), alpha forced to 255 unless the window is
seen through, into a buffer from `Rpixels_alloc`.

### 5.7 Waiting, device loss

- `WaitIdle`: commits the upload command buffer, then commits an empty command
  buffer and waits for it (`waitUntilCompleted`): the queue being in order,
  everything submitted before is finished.
- `Shutdown`: WaitIdle, then every object is released (set to nil).
- Device loss: when a command buffer completes with
  `MTLCommandBufferStatusError` and the error is
  `MTLCommandBufferErrorDeviceRemoved` (an external GPU unplugged on a Mac;
  macOS only, compared by its value 11: the constant does not exist on iOS and
  is deprecated from macOS 27),
  the backend sets its `device_lost` flag (atomic) and calls
  `Rbackend_device_lost()`, which is thread-safe. RenderFrame then returns
  at once until Raven restarts the backend (`render/device.c`: Shutdown,
  Init, surfaces, textures, shaders made again). `MTLCommandBufferErrorNotPermitted`
  (GPU work refused in the background on iOS) is expected and silent. Any other
  error is reported once with `rvn_error(R_ERROR_BACKEND, R_SEVERITY_ERROR,
  "Metal: a frame failed: %s", ...)`.
- `RBackendInitInfo::enable_validation` has no effect: Metal's validation is
  switched on outside the process (`MTL_DEBUG_LAYER=1`,
  `MTL_SHADER_VALIDATION=1`).

### 5.8 iOS: background, rotation, the surface

- iOS terminates an application that sends GPU work while it is in the
  background. `uikit_platform.m` calls `rvn_metal_set_suspended(R_TRUE)` (a
  private function of the backend, declared in `renderer.h` under
  `RAVEN_BACKEND_METAL_ENABLED`) from `UIApplicationDidEnterBackgroundNotification`,
  and `rvn_metal_set_suspended(R_FALSE)` from
  `UIApplicationWillEnterForegroundNotification`, after which it posts
  `RVN_PEVENT_EXPOSE` to every window so that they are drawn again.
  Suspending takes the backend's suspension lock, sets the flag, and waits
  for the last command buffer committed (the GPU is idle when the
  notification returns). The render thread holds the same lock across "is
  rendering suspended? / commit", so no command buffer can be committed after
  the flag is set. While suspended, frames and upload flushes return without
  committing; textures and uploads are kept.
- The `CAMetalLayer` of the view lives as long as the view: unlike a Vulkan
  surface it is not lost when the application goes to the background. All
  textures, pipelines and backdrop images are kept, nothing is made again.
  The surface lost / ready events discussed for Vulkan on iOS are therefore
  not needed by this backend.
- `layoutSubviews` already sets `contentsScale` and `drawableSize` before the
  first frame and at each rotation, and posts the resize; RenderFrame sets
  `drawableSize` again when the framebuffer size of a frame differs (5.2, 3),
  so a frame is never drawn at a stale size.

## 6. Selection, build and platforms

### 6.1 The enumeration

`R_BACKEND_METAL` is appended to `RBackend` in `raven_core.h`, after
`R_BACKEND_WEBGL` (value 0x0005); no existing value changes:

```c
	/** Browser renderer (Emscripten, WebGL 2). */
	R_BACKEND_WEBGL,
	/** Built-in Metal renderer (macOS, iOS). */
	R_BACKEND_METAL
```

`R_BACKEND_DEFAULT` (0) is added first, a name for the value 0 that already
meant "the default": `Rinit(R_BACKEND_DEFAULT)` reads well in every binding.
`RInitDesc::backend` is documented as "R_BACKEND_DEFAULT (0) selects WebGL in
browser builds, Metal on macOS and iOS when it is compiled, Vulkan otherwise".
The tools (Raven Designer, the theme editor, the SDK installer), the project
templates of the installer, `examples/languages` and the samples of the
documentation ask for `R_BACKEND_DEFAULT`, so on macOS none of them needs
MoltenVK; the installer's bundles no longer carry it. The bindings are
generated again (`python3 tools/bindgen/bindgen.py`).

### 6.2 Choosing the backend (context.c)

```c
	if (desc.backend == R_BACKEND_DEFAULT) {
#if defined(RAVEN_BACKEND_WEBGL_ENABLED)
		desc.backend = R_BACKEND_WEBGL;
#elif defined(RAVEN_BACKEND_METAL_ENABLED)
		desc.backend = R_BACKEND_METAL;
#else
		desc.backend = R_BACKEND_VULKAN;
#endif
	}
```

and in `rvn_select_backend`:

```c
		case R_BACKEND_METAL:
#if defined(RAVEN_BACKEND_METAL_ENABLED)
			return rvn_backend_metal();
#else
			rvn_error(R_ERROR_BACKEND, R_SEVERITY_FATAL, "Raven was built without the Metal backend");
			return NULL;
#endif
```

`R_BACKEND_VULKAN` asked for explicitly still gives Vulkan when it is
compiled. Elsewhere in the core:

- `renderer.h` declares `const RBackendVTable* rvn_backend_metal(void);` and
  `void rvn_metal_set_suspended(int suspended);` under
  `#if defined(RAVEN_BACKEND_METAL_ENABLED)`, and the built-in effect lookup
  of 7 (`rvn_effect_index_of`), unconditionally;
- `rvn_frame_pacing` (context.c) is true for `R_BACKEND_METAL` as for
  `R_BACKEND_VULKAN`: both present to the window themselves;
- the warning of `render/device.c` names the backend from its table
  (`"Metal"`, `"Vulkan"`) instead of testing for Vulkan only.

The table is named `"Metal"`; `CreateShader` and `DestroyShader` are
provided.

### 6.3 CMake

```cmake
option(RAVEN_BACKEND_METAL "Compile the Metal backend (macOS, iOS)" ${APPLE})
```

declared beside `RAVEN_BACKEND_VULKAN` (`APPLE` is false in Emscripten
builds), and after the Vulkan block:

```cmake
if(RAVEN_BACKEND_METAL)
	if(NOT APPLE)
		message(FATAL_ERROR "The Metal backend is only available on macOS and iOS")

	set_source_files_properties(${RAVEN_METAL_SOURCES} PROPERTIES COMPILE_OPTIONS "-fobjc-arc;-Wno-overlength-strings")

	list(APPEND RAVEN_LIBRARIES ${RAVEN_METAL_FRAMEWORK} ${RAVEN_QUARTZCORE_FRAMEWORK} ${RAVEN_FOUNDATION_FRAMEWORK})

```

MoltenVK: `RavenVulkanHeaders` is only included by the Vulkan block, and the
SPIR-V arrays that `shader.c` includes from `src/render/vulkan/generated/`
are plain `uint32_t` data, compiled with or without the Vulkan backend.

### 6.4 Platforms

**Cocoa.** `rvn_cocoa_install_layer` already gives every content view (and

from the screen, and `rvn_cocoa_window_get_native` passes that layer as
`RNativeWindow::window`. Nothing in `cocoa_platform.m` depends on Vulkan, so

### 6.5 Choosing the backend from the environment (examples and tests)

`examples/common/example.h` reads `RAVEN_BACKEND` in `example_init`:
`metal`, `vulkan` or `null` (case does not matter) select that backend;
unset or empty select 0, the default of the platform (so the desktop
examples use Metal on macOS from now on); any other value is reported on
stderr and the default is used. Browser builds keep 0. An example that needs
one backend calls `example_init_backend(name, backend)`: `viewport_vulkan`,
which draws with Vulkan itself, asks for `R_BACKEND_VULKAN`.
`raven_theme_editor` asks for 0 instead of `R_BACKEND_VULKAN`.

```sh
RAVEN_BACKEND=metal  RAVEN_EXAMPLE_FRAMES=30 RAVEN_EXAMPLE_CAPTURE=metal.ppm  ./raven_glass
RAVEN_BACKEND=vulkan RAVEN_EXAMPLE_FRAMES=30 RAVEN_EXAMPLE_CAPTURE=vulkan.ppm ./raven_glass
```

`tests/test_render.c` reads the same variable (default: `vulkan`, its
behaviour so far), CHECKs that a viewport callback receives that backend (and,
on Metal, a non-NULL `metal_encoder`), and runs the tests of the Vulkan API
(`test_vulkan_api`, `test_device_lost`) only on Vulkan, and only when they

built when either backend is; ctest gets `test_render` (environment

## 7. Effects

`CreateShader(shader, spirv, size)` cannot run SPIR-V: Metal has no SPIR-V
front end, and translating it would take SPIRV-Cross, a dependency this
backend refuses. The built-in effects are recognised instead, and have their
own MSL ports.

`shader.c` gains

```c
/** Index of the built-in effect whose SPIR-V this is (REffect - R_EFFECT_AURORA), or -1. Thread-safe. */
int rvn_effect_index_of(const uint32_t* spirv, size_t size);
```

which compares the words with the eight SPIR-V arrays of `g_effects` (size,
then `memcmp`). The table is constant data, so the render thread may call it,
unlike `rvn_shader_get` (the WebGL backend reads `rvn_shader_t::effect`, but
it renders on the UI thread). It also recognises an application that loads
the same `.spv` file as a built-in effect, which is right: it is the same
effect.

| REffect | Index | GLSL | MSL | Reads the backdrop |
|---|---|---|---|---|
| `R_EFFECT_AURORA` | 0 | `effects/aurora.frag` | `effects/aurora.metal` | no |
| `R_EFFECT_SHIMMER` | 1 | `effects/shimmer.frag` | `effects/shimmer.metal` | no |
| `R_EFFECT_NEON` | 2 | `effects/neon.frag` | `effects/neon.metal` | no |
| `R_EFFECT_RIPPLE` | 3 | `effects/ripple.frag` | `effects/ripple.metal` | yes (`raven_backdrop`) |
| `R_EFFECT_PLASMA` | 4 | `effects/plasma.frag` | `effects/plasma.metal` | no |
| `R_EFFECT_GRAIN` | 5 | `effects/grain.frag` | `effects/grain.metal` | no |
| `R_EFFECT_SPOTLIGHT` | 6 | `effects/spotlight.frag` | `effects/spotlight.metal` | no |
| `R_EFFECT_MESH` | 7 | `effects/mesh.frag` | `effects/mesh.metal` | no |

Each MSL file defines `float4 raven_effect(RAVEN_EFFECT_ARGS)` and nothing
else, and its fragment entry point is always `rvn_effect_fragment` from
`effect.metal` (2.6). The effects use `atan` with two arguments (neon:
`atan2`), `mat2` (`float2x2`), `raven_fbm`, `raven_hash`, `raven_has_pointer`
and, for ripple, `raven_backdrop`.

In the backend:

- index *n* >= 0: the library of effect *n* is compiled the first time
  (common + effect + `rvn_mtl_effect_sources[n]`, kept until Shutdown), its
  pipeline state made with `rvn_ui_vertex` and `rvn_effect_fragment`, and
  stored for that shader handle (by `R_ID_INDEX`). If the library or the
  pipeline cannot be made, the compiler's message is reported once with
  `rvn_error(R_ERROR_BACKEND, R_SEVERITY_ERROR, "Metal: the effect %s cannot be compiled: %s", ...)`
  and the shader is drawn with the fallback;
- index -1 (an effect of the application): the shader is drawn with the
  fallback pipeline (2.3, a rounded rectangle in its `color`, which is what
  the contract allows a backend without custom shaders). The first such
  shader is reported once with `rvn_error(R_ERROR_BACKEND, R_SEVERITY_WARNING,
  "Metal: effects given as SPIR-V cannot run on the Metal backend: they are drawn as rounded rectangles")`.

`CreateShader` returns R_TRUE in both cases: the shader is usable (the core
keeps it, and draws it), only its look is reduced. `DestroyShader` drops the
pipeline; command buffers in flight keep it alive themselves.

This is a documented limitation of the backend: an application that ships
its own SPIR-V effects and needs them on Apple systems asks for
`R_BACKEND_VULKAN`. A way for applications to give an MSL version of their
effects (like `Rweb_shader_create` for WebGL) can come later without changing
anything described here; `raven_shader.h` says, next to the WebGL remark,
that the Metal backend runs the built-in effects and draws the others as
rectangles.

## 9. Checking the result

### 9.1 Compiling MSL without Xcode

The run-time compiler is on every Mac. This throwaway program (kept out of
the repository) compiles a set of `.metal` files in the given order and
prints the functions, or the compiler's errors:

```objc
/* clang -fobjc-arc -framework Metal -framework Foundation mslcheck.m -o mslcheck
 * ./mslcheck common.metal ui.metal */
#import <Metal/Metal.h>
#include <stdio.h>

int main(int argc, const char** argv) {
	@autoreleasepool {
		NSMutableString* source = [NSMutableString string];
		for (int i = 1; i < argc; i++) {
			NSString* text = [NSString stringWithContentsOfFile:@(argv[i]) encoding:NSUTF8StringEncoding error:nil];
			if (!text) { fprintf(stderr, "cannot read %s\n", argv[i]); return 1; }
			[source appendString:text];
		}
		id<MTLDevice> device = MTLCreateSystemDefaultDevice();
		MTLCompileOptions* options = [MTLCompileOptions new];
		options.fastMathEnabled = NO;
		NSError* error = nil;
		id<MTLLibrary> library = [device newLibraryWithSource:source options:options error:&error];
		if (error) fprintf(stderr, "%s\n", error.localizedDescription.UTF8String);
		if (!library) return 1;
		for (NSString* name in library.functionNames) printf("%s\n", name.UTF8String);
	}
	return 0;
}
```
