The Raven manual

Raven is a GUI library in C11 for editors and tools: native windows on Windows, Linux and macOS, drawn with Vulkan, with a layout in the manner of Slate, interfaces written in XML or in code, a text editor for code, docking, glass materials, translations, accessibility, and bindings for seven other languages. This guide explains every part of it with examples. The two other pages are references: every XML tag and attribute, and every function of the C API.

Raven 0.1. The public API may still change before 1.0.

1. A first program

The whole API is one include. A window, a box, a label and a button:

#include <Raven.h>

static void on_quit(Rid button, void* user_data) {
    (void)button;
    (void)user_data;
    Rquit(0);
}

int main(void) {
    if (!Rinit(R_BACKEND_VULKAN)) return 1;

    Rid window = Rwindow_create("Hello", 420, 220, R_WINDOW_DEFAULT);
    Rid box = Rwidget_create(R_WIDGET_VBOX);
    Rpanel_set_spacing(box, 12);
    Rslot_set_halign(box, R_HALIGN_CENTER);
    Rslot_set_valign(box, R_VALIGN_CENTER);
    Rwindow_set_content(window, box);

    Rwidget_add_child(box, Rlabel_create("Hello from Raven"));
    Rid quit = Rwidget_add_child(box, Rbutton_create("Quit"));
    Rbutton_set_clicked_callback(quit, on_quit, NULL);

    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return Rget_exit_code();
}

The same window, written in XML and loaded by the program:

<Window Title="Hello" Width="420" Height="220">
    <VBox Spacing="12" Slot.HAlign="Center" Slot.VAlign="Center">
        <Label>Hello from Raven</Label>
        <Button Text="Quit" OnClicked="app.quit"/>
    </VBox>
</Window>
#include <Raven.h>

static void on_quit(Rid sender, const char* action, void* user_data) {
    (void)sender;
    (void)action;
    (void)user_data;
    Rquit(0);
}

int main(void) {
    if (!Rinit(R_BACKEND_VULKAN)) return 1;
    Raction_bind("app.quit", on_quit, NULL);
    if (Rwindow_create_from_xml_file("hello.xml") == R_INVALID_ID) return 1;
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}

Built with CMake, against an installed Raven:

cmake_minimum_required(VERSION 3.16)
project(hello C)
find_package(raven REQUIRED)            # -DCMAKE_PREFIX_PATH=<the Raven package>
add_executable(hello main.c)
target_link_libraries(hello PRIVATE raven::raven)

Or with the interface in its own file, main.xml, loaded when the program starts (see Any language), and made by looking at it in the designer.

2. Building Raven

Raven needs CMake 3.16 or newer and a C11 compiler. On Linux it also needs the X11 development package. The Vulkan headers are taken from the Vulkan SDK when it is installed and downloaded during the configuration otherwise; no Vulkan library is linked (it is loaded when the program runs). Each build gives the library, the designer, the theme editor, the examples and the tests.

The latest version: from the sources

The releases and the packages of the bindings (PyPI, NuGet, crates.io, LuaRocks, Maven Central) are made from time to time; the repository moves every day. To have the latest features, clone the repository and build Raven yourself rather than downloading a release: what this manual describes may not be in the last release yet. It takes a few minutes:

git clone https://github.com/oscar-soirey/Raven.git
cd Raven
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel

git pull and the same cmake --build bring it up to date later. Add -DRAVEN_BUILD_SHARED=ON for the shared library the bindings load. The sections below give the details for each system.

Linux: Wayland and X11

Raven speaks both. In a Wayland session it opens native Wayland windows; elsewhere, or where Wayland cannot be used, X11 windows (through XWayland in a Wayland session). Nothing of Wayland is needed to build: libwayland-client and libxkbcommon are opened when the program starts, and the protocols are compiled in.

  • Title bars: drawn by the compositor (xdg-decoration: KDE, wlroots, Hyprland...), or by libdecor where the compositor draws none (GNOME). With neither, Raven uses X11, whose window manager draws them. Windows with a custom header (R_WINDOW_CUSTOM_HEADER) draw their own everywhere.
  • Scale: fractional scales (fractional-scale-v1 and viewporter): the window is drawn at its size in pixels, sharp at 125 % or 150 %.
  • Keyboard: the layout of the compositor (xkbcommon), key repeat, dead keys and compose sequences.
  • Also: cursors (cursor-shape-v1, or the cursor theme), clipboard, files and text dropped from other applications, native viewports as sub-surfaces, window icons (xdg-toplevel-icon), blur behind transparent windows (ext-background-effect).
  • Not possible on Wayland: an application cannot place its windows or know where they are (Rwindow_set_position and Rwindow_center do nothing, Rwindow_get_position gives 0, 0), keep one above the others, or fade a whole window.

RAVEN_WINDOW_SYSTEM=x11 or =wayland overrides the choice. Rwindow_get_native_handle tells which one a window got: with R_WINDOW_SYSTEM_WAYLAND, display is the wl_display* and window the wl_surface*. RAVEN_APP_ID names the application to the desktop (default: the name of the executable); it should match its .desktop file.

Using Raven from a project

find_package(raven REQUIRED)                  # an installed package
target_link_libraries(app PRIVATE raven::raven)

add_subdirectory(Raven)                       # or the sources, without installing
target_link_libraries(app PRIVATE raven::raven)

An installed package holds include/, lib/ (the library and lib/cmake/raven), bin/ (raven_designer, and raven.dll in a shared build) and share/raven/bindings. With a shared library on Windows, define RAVEN_USE_DLL (CMake does it through the target).

Booleans are int (R_TRUE, R_FALSE), colors are four floats from 0 to 1, strings are UTF-8 and always copied by the library. A string returned by the library stays valid until the next call that returns one of the same kind: copy it to keep it.

Handles and errors

Every object is a Rid: windows, widgets, fonts, textures, timers, tree items, documents. A handle carries a generation, so using a deleted object is reported instead of crashing, and R_INVALID_ID is returned on failure. Deleting a widget deletes its children; deleting a window deletes its content.

static void on_error(RError code, RSeverity severity, const char* detail) {
    fprintf(stderr, "[%s] %s: %s\n", Rseverity_to_string(severity), Rerror_to_string(code), detail);
}

Rerror_set_callback(on_error);        /* before Rinit, to see its errors too */

const char* detail;
RSeverity severity;
if (Rerror_get_last(&detail, &severity) != R_NO_ERROR) puts(detail);

The loop

Raven has no loop of its own. The application asks for one frame at a time:

while (Rdraw_frame()) {               /* a game or an engine: never waits    */
    update_and_render_my_scene();
}

while (Rwait_frame(-1.0)) {}          /* a tool: sleeps until something happens */

Rdraw_frame processes the events, runs the timers and the posted tasks, lays out, paints and submits the windows that changed; a window in which nothing changed is not drawn again. Rwait_frame first sleeps until there is something to do (an event, a timer, an animation still moving, a task); its argument is the longest sleep in seconds, negative for no limit. Both return R_FALSE once Rquit was called or the last window closed; Rget_exit_code gives the code. Rset_frame_callback runs a function once per frame, also while the system holds the thread in a loop of its own (on Windows, while a window is moved or resized).

RInitDesc desc = { 0 };               /* zero: the default of every field */
desc.backend = R_BACKEND_VULKAN;
desc.app_name = "My tool";
desc.worker_threads = 0;              /* one per spare core; negative: none */
desc.ui_scale = 1.25f;                /* on top of the scale of the monitor */
desc.disable_vsync = R_FALSE;
desc.enable_validation = R_FALSE;     /* the Vulkan validation layer, when installed */
if (!Rinit_ex(&desc)) return 1;

One thread for the interface

The thread that called Rinit is the UI thread: every function is called from it, except those documented as thread-safe (Rtask_post, Rtask_run_async, Rwake_up, Rquit, Rwindow_request_redraw, Rget_time, Rmemory_alloc, Rmemory_realloc, Rmemory_free, Rmemory_get_stats). Another thread changes the interface by posting a task (Threads). A call from the wrong thread is reported as R_ERROR_WRONG_THREAD.

Rwindow_set_continuous_redraw draws every frame (a game view); Rwindow_request_redraw asks for one more.

5. Widgets

An interface is a tree of widgets. A widget is created by type, put in a parent, found again by name, and deleted with its children:

Rid panel  = Rwidget_create(R_WIDGET_VBOX);
Rid label  = Rwidget_add_child(panel, Rlabel_create("Name"));     /* returns the child */
Rid input  = Rwidget_add_child(panel, Rwidget_create(R_WIDGET_TEXT_INPUT));
Rwidget_set_name(input, "name");

Rid found  = Rwidget_find(window, "name");          /* in a window, or under any widget */
Rid parent = Rwidget_get_parent(found);
int count  = Rwidget_get_child_count(panel);
Rwidget_insert_child(panel, Rbutton_create("First"), 0);
Rwidget_remove_child(panel, label);                 /* removed and deleted */
Rwidget_clear_children(panel);
Rwidget_destroy(panel);

The types: panels (R_WIDGET_VBOX, R_WIDGET_HBOX, R_WIDGET_GRID, R_WIDGET_UNIFORM_GRID, R_WIDGET_OVERLAY, R_WIDGET_BORDER, R_WIDGET_SIZE_BOX, R_WIDGET_SPACER, R_WIDGET_SCROLL_BOX, R_WIDGET_SPLITTER, R_WIDGET_WRAP_BOX, R_WIDGET_CANVAS, R_WIDGET_SWITCHER, R_WIDGET_TAB_VIEW, R_WIDGET_EXPANDER, R_WIDGET_BACKGROUND_BLUR), controls (R_WIDGET_LABEL, R_WIDGET_BUTTON, R_WIDGET_CHECKBOX, R_WIDGET_SLIDER, R_WIDGET_PROGRESSBAR, R_WIDGET_IMAGE, R_WIDGET_TEXT_INPUT, R_WIDGET_SPIN_BOX, R_WIDGET_COMBO_BOX, R_WIDGET_SEPARATOR, R_WIDGET_LIST_VIEW, R_WIDGET_TREE_VIEW, R_WIDGET_TILE_VIEW, R_WIDGET_MENU_BAR, R_WIDGET_MENU, R_WIDGET_MENU_ITEM, R_WIDGET_TEXT_EDITOR), the shell (R_WIDGET_HEADER_BAR, R_WIDGET_DOCK_AREA, R_WIDGET_ISLAND, R_WIDGET_FILE_BROWSER), tools (R_WIDGET_COLOR_PICKER, R_WIDGET_TIMELINE, R_WIDGET_NODE_GRAPH, R_WIDGET_BLOCK_EDITOR) and your own (R_WIDGET_VIEWPORT, R_WIDGET_CUSTOM).

6. Layout

Layout is the two passes of Slate: each widget computes the size it wants, from the leaves up; then each panel gives a rectangle to its children, from the root down. How a child is placed is stored on the child, in its slot, and read by its parent:

Rid row  = Rwidget_add_child(parent, Rwidget_create(R_WIDGET_HBOX));
Rpanel_set_spacing(row, 8);
Rid name = Rwidget_add_child(row, Rwidget_create(R_WIDGET_TEXT_INPUT));
Rslot_set_fill(name, 1.0f);                   /* takes the free width */
Rid ok   = Rwidget_add_child(row, Rbutton_create("OK"));
Rslot_set_valign(ok, R_VALIGN_CENTER);        /* its own height, centered */
Rslot_set_padding(ok, 8, 0, 0, 0);            /* left, top, right, bottom */

Rslot_set_valign (R_VALIGN_FILL, _TOP, _CENTER, _BOTTOM)HBox, Grid, Overlay, Border, SizeBox, ScrollBox, Switcher, a window

Right to left

A language written from right to left mirrors the layouts: boxes, grids, menus, scroll bars and alignments start on the right. By default (R_DIRECTION_AUTO) the windows follow the language in use; Rset_layout_direction(R_DIRECTION_RTL) or R_DIRECTION_LTR forces one direction for every window, and Rwidget_set_direction gives one to a part of a window (R_DIRECTION_INHERIT goes back to its parent; Direction="RightToLeft" in XML).

Raw input

A widget can see the mouse and the keyboard before its own class does; returning R_TRUE consumes the event. Events bubble from the widget under the pointer (or with the focus) up to the window.

static int on_event(Rid widget, const REvent* e, void* user_data) {
    switch (e->type) {
    case R_EVENT_MOUSE_DOWN:
        if (e->button == R_MOUSE_RIGHT) { open_menu(e->x, e->y); return R_TRUE; }
        if (e->clicks == 2) { rename_item(); return R_TRUE; }
        break;
    case R_EVENT_MOUSE_WHEEL:
        zoom_by(e->wheel_y);
        return R_TRUE;
    case R_EVENT_KEY_DOWN:
        if (e->key == R_KEY_DELETE && !(e->modifiers & R_MOD_CTRL)) { delete_selection(); return R_TRUE; }
        break;
    case R_EVENT_TEXT:          /* e->codepoint: a typed character */
    default:
        break;
    }
    return R_FALSE;             /* not mine: the widget and its parents get it */
}

Rwidget_set_event_callback(widget, on_event, NULL);
Rwindow_set_event_hook(window, on_window_event, NULL);   /* the whole window, before any widget */

REvent gives the position in the window (x, y) and in the widget (local_x, local_y), the movement (delta_x, delta_y), the wheel, the button and the number of clicks, the key, the modifiers, whether the key repeats and the typed character.

Fingers, pens and trackpads

Touch screens, pens and trackpads work with nothing written: Raven reads them on every platform (Windows: WM_POINTER and Direct Manipulation for precision touchpads; Linux: XInput 2 on X11, the touch, tablet and pointer-gestures protocols on Wayland; macOS: the pressure of tablets and the gestures of the trackpad) and makes them drive the widgets as they are:

  • a tap clicks; a finger that moves drags as the mouse would, except over what scrolls (ScrollBox, lists, trees, tiles, the text editor, the timeline, the graphs): there the content follows the finger and keeps going when it is flicked;
  • a finger that rests opens the context menu (a right click);
  • two fingers pinch to zoom and pan where a widget zooms (NodeGraph, TextEditor, Timeline, BlockEditor) or scrolls;
  • a pen is a mouse with a pressure, its barrel button is the right button, and the palm resting on the screen while a pen is near is ignored.

On a trackpad:

  • two fingers that move scroll, the content following them by the pixel; a flick keeps going (made by the system on Windows and macOS, by Raven on Wayland). The wheel event says so: REvent::wheel_precise is set, and wheel_x, wheel_y are fractions of a line (48 logical units). Canvases pan instead of zooming (NodeGraph, BlockEditor), and what steps by notches (a focused SpinBox, the stops of the zoom of a graph) adds the fractions up;
  • two fingers that pinch or turn zoom and rotate as on a touch screen: the same RGestureEvent, with device set to R_GESTURE_DEVICE_TRACKPAD and x, y at the pointer;
  • three or more fingers swiped across go back (toward the right) or forward: the side buttons of a mouse, R_MOUSE_X1 and R_MOUSE_X2, are pressed where the pointer is (a FileBrowser goes back and forward in its history). The gesture callback sees the swipe first (kind is R_GESTURE_SWIPE, with fingers and total_x, total_y) and may take it.

What changes it: the settings of the application or of one window, the mode of a widget, and the events themselves for a widget that wants them (drawing with the pressure, a gesture of its own). A callback that returns R_TRUE takes the finger, the stroke or the gesture: the library does nothing else with it.

    if (e->wheel_precise) pan_by(e->wheel_x * 48.0f, e->wheel_y * 48.0f);   /* a trackpad */

15. Themes, styles and materials

A theme gives every widget its look: about forty colors (roles, not widgets: accent, panel, text...), twenty metrics (font size, corner radius, height of a control...), a material, a font, the colors of code, and styles for a type of widget, a class, or both. Six themes are built in.

A theme starts from a look (Rlook_set): the ones of Raven, or those of the platforms, imitated closely: Windows 11 (R_LOOK_WINDOWS_...), macOS Sequoia (R_LOOK_MACOS_...), macOS 26 with Liquid Glass (R_LOOK_MACOS_GLASS_...: glass on header bars and their buttons, menus, drop-down lists, tooltips and sheets, knobs that turn into a lens of glass while held, the content opaque), GNOME (R_LOOK_GNOME_...), or the one of the platform the program runs on (R_LOOK_NATIVE_..., which gives macOS Glass from macOS 26 on).

The theme editor

raven_theme_editor [theme.xml] makes theme files by looking at them. On the left, everything a theme holds; on the right, a preview made of real widgets (controls, an application, code, lists, a dialog) drawn with the theme as it is being made, and alive: hover, type and drag in it.

  • Theme: the name, the look it starts from, dark or light, the material, the motion, the accent, the font and the wallpaper. Generate the palette works out the 36 colors and the syntax colors from the accent (Tint: how much the surfaces take its hue; Depth: how far apart they are), with text that reads; Surprise me tries another accent.
  • Colors, Sizes, Code: each color role, metric, glass multiplier and syntax color, showing the value of the look until one is set; × goes back to it.
  • Styles: the <Style> rules as text, with ready-made ones to add; a mistake shows under the text, and the preview keeps the last good theme.
  • Check: the contrast of the pairs of colors people read, measured as WCAG 2 does (AA, AAA, low, failing). Fix changes the lightness of the color in front as little as it takes; Fix every pair does it everywhere but on the accent.
  • XML: the file as it will be saved, editable by hand. Copy as C gives it as a C string, with the calls that load and use it.

Saved version, above the preview, shows the theme as it was last opened or saved, to compare with the changes.

Undo and redo cover every change; F7 opens the preview in a window of its own, with the wallpaper of the theme. 16. Custom widgets, drawing and animation

A R_WIDGET_CUSTOM is measured and painted by two callbacks, and receives its input through Rwidget_set_event_callback. Coordinates are logical units from its top left corner.

#include <Raven.h>

typedef struct gauge_t {
    float level;          /* 0..1 */
    RSpring shown;        /* the level drawn, gliding to `level` */
} gauge_t;

static void gauge_measure(Rid widget, float* width, float* height, void* user_data) {
    (void)widget; (void)user_data;
    *width = 160;
    *height = 18;
}

static void gauge_paint(Rid widget, RPainter* p, float width, float height, void* user_data) {
    gauge_t* g = (gauge_t*)user_data;
    float level = Rdraw_spring(p, &g->shown, g->level, R_MOTION_BOUNCY);
    float r, gr, b, a;
    (void)widget;
    Rtheme_get_color(R_COLOR_ACCENT, &r, &gr, &b, &a);
    Rdraw_rect(p, 0, 0, width, height, height * 0.5f, 1, 1, 1, 0.08f);
    Rdraw_rect(p, 0, 0, width * level, height, height * 0.5f, r, gr, b, a);
    Rdraw_text(p, R_INVALID_ID, 11, 8, 2, level > 0.9f ? "full" : "", 1, 1, 1, 1);
}

static int gauge_event(Rid widget, const REvent* e, void* user_data) {
    gauge_t* g = (gauge_t*)user_data;
    float x, y, w, h;
    if (e->type != R_EVENT_MOUSE_DOWN) return R_FALSE;
    Rwidget_get_rect(widget, &x, &y, &w, &h);
    g->level = e->local_x / w;
    Rwidget_invalidate(widget);           /* paint again */
    return R_TRUE;
}

static gauge_t g_gauge = { 0.4f, { 0.0f, 0.0f, 0 } };

int main(void) {
    Rid window, gauge;
    if (!Rinit(R_BACKEND_VULKAN)) return 1;
    window = Rwindow_create("Gauge", 320, 120, R_WINDOW_DEFAULT);
    gauge = Rwidget_create(R_WIDGET_CUSTOM);
    Rcustom_set_measure_callback(gauge, gauge_measure, &g_gauge);
    Rcustom_set_paint_callback(gauge, gauge_paint, &g_gauge);
    Rwidget_set_event_callback(gauge, gauge_event, &g_gauge);
    Rslot_set_halign(gauge, R_HALIGN_CENTER);
    Rslot_set_valign(gauge, R_VALIGN_CENTER);
    Rwindow_set_content(window, gauge);
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}

The painter draws rounded rectangles and their outlines, circles, lines, curves, triangles, images, text and glass (Rdraw_glass), clipped with Rdraw_push_clip_rect. Rxml_register_tag gives such a widget a tag of its own (XML).

Springs

Everything moves with springs, as on a phone: buttons squash and bounce back, switches slide, popups pop out of what opened them, lists stretch at their ends. In a custom widget, Rdraw_spring pulls a value to its target and keeps the window drawing while it moves; Rwait_frame sleeps again when everything rests. The motions are R_MOTION_SNAPPY, R_MOTION_SMOOTH, R_MOTION_BOUNCY and R_MOTION_WOBBLY; Rspring_kick gives a spring a push, Rspring_set puts it somewhere without moving.

A viewport shows what the application renders: a 3D scene, a video, an emulator. Three ways:

22. Web pages

raven_web.h shows real web pages by driving a browser of the Chromium family that is already installed (Edge, which comes with Windows; Chrome, Chromium, Brave...): the page arrives as pictures in a texture, the input goes back, scripts run both ways. It contains no browser and needs nothing to build. Without a browser, a view says so and stays safe to call.

23. Threads

The thread of Rinit owns the interface. A render thread owns the GPU, and a job system of worker threads paints large trees in parallel and runs your work.

typedef struct job_t { char path[260]; char* result; } job_t;

static void job_done(void* user_data) {           /* on the UI thread */
    job_t* job = (job_t*)user_data;
    Rtext_editor_set_text(g_editor, job->result);
    Rmemory_free(job->result);
    Rmemory_free(job);
}

static void job_run(void* user_data) {            /* on a worker thread: no widget here */
    job_t* job = (job_t*)user_data;
    job->result = load_and_format(job->path);
    Rtask_post(job_done, job);                    /* back to the UI thread, and wakes Rwait_frame */
}

job_t* job = (job_t*)Rmemory_alloc(sizeof(job_t));
snprintf(job->path, sizeof(job->path), "%s", path);
Rtask_run_async(job_run, job);

/* split a loop over the workers and this thread; returns when all is done */
static void blur_rows(Ruint begin, Ruint end, void* image) { /* rows begin..end-1 */ }
Rparallel_for(height, 16, blur_rows, image);

Viewport draw callbacks run on the render thread. Rwake_up wakes Rwait_frame from any thread; Ris_ui_thread tells where you are.

24. Memory

Raven does not call malloc: it takes memory from the system by regions of 4 MB and hands it out with its own heap (TLSF: constant time, neighbours merged when freed). The bundled font and image decoders use it too.

static void* my_alloc(size_t size, void* user) { return engine_alloc(size, 16); }
static void* my_realloc(void* p, size_t size, void* user) { return engine_realloc(p, size, 16); }
static void my_free(void* p, void* user) { engine_free(p); }

RAllocator mine = { my_alloc, my_realloc, my_free, NULL };
Rset_allocator(&mine);                 /* before Rinit: every block goes through your functions */

RMemoryStats stats;
Rmemory_get_stats(&stats);             /* bytes in use, peak, blocks, taken from the system */
printf("%zu bytes in %zu blocks\n", stats.used_bytes, stats.allocation_count);
Rmemory_check();                       /* walks the heap: R_FALSE when it is corrupted */
Rmemory_trim();                        /* gives back the regions that hold nothing */

Rset_allocator(Rallocator_get_system()), or RAVEN_ALLOCATOR=system, uses malloc instead (what Valgrind and heap profilers follow; the default in a build with AddressSanitizer). After Rshutdown, allocation_count is 0: anything else is a leak of the library.

26. The designer

raven_designer [folder | interface.xml] makes the interfaces of Raven (.xml) by looking at them, in a folder. It is a tool, not an IDE: nothing is built nor compiled there, and it has no code editor. The program that loads the interfaces is written in any language, with its own tools. It opens on a start page: open a folder, open an interface, the recent folders. The designer page sums up its panels and its keys.

Four tabs

Each kind of file has its own tab at the top of the window, and each tab keeps its own file open and its own undo; Ctrl+1 to Ctrl+4 switch:

  • Window: the interfaces of the folder (a <Window>, a panel, a form), in the visual editor.
  • Widget: the widget libraries (<Widgets> with <Widget Name="Card">...). The preview shows one of each tag declared; the windows of the folder can then use them.
  • Theme: the theme editor itself, built in: the themes of the folder in a list, every color, size and rule, its preview and its contrast check. Saved, the windows of the folder wear it.
  • Translations: the tables (.csv) as a grid, one row per key, one column per language; what is typed shows in the preview at once.

Files shows what the tab in front works on, sub-folders included. A right click: open, new (from a template, in the folder), delete. The folder is followed live: a file another program writes shows at once; the file open is read again when it has no unsaved changes here; a theme or a table that changes changes the preview. The combo at the top right dresses the designer itself: a look of Raven, or a theme of the folder.

The visual editor

The same document, five ways, kept in step:

  • Widgets: what can be added (the tags of the library and those the folder declares). Drag one into the preview, or double click to add it inside the selection.
  • Tree: the elements; move up, down, out, in; duplicate, delete, wrap, unwrap; copy and paste as XML.
  • Preview: the interface built for real. A click selects (an outline, the inside left clear); drag an element to move it, a line shows where it goes and Escape cancels. With Use it (F6) it reacts as the interface will.
  • Properties: every attribute of the selection, by kind of value.
  • XML: the text, with completion of the tags, the attributes and the @keys; a mistake is underlined and listed in Problems while the last good version stays shown.

The preview: devices, themes, languages

Above the preview: the size it is shown in (the size the XML gives, a phone, a phone on its side, a tablet, a laptop, a desktop), the look or theme it wears (the looks of Raven, and the themes of the folder), and its language (the columns of the tables, right to left included). Open in a window (or F7) shows the interface in a window of its own, at its real size, following every change live; its bar chooses the device, the theme and the language, and goes back to the designer.

The theme of a <Window> is written in it: choosing one sets its Theme attribute (a look by its name, a theme of the folder by the path of its file), and the preview and the window of F7 wear it while the designer keeps its own appearance. Same as the designer removes the attribute.

The island: Ctrl+K

The island at the top of the window is the command center of the designer. It unfolds when the pointer is over it. Folded, it says which file is open and whether it has unsaved changes, what is selected, and how many problems the interface has. Ctrl+K unfolds it on one search for everything: a widget to add inside the selection (add slider), an interface to open (open settings), a tab, a command (wrap in a vbox, preview in a window, undo, new theme...), a language or a theme for the preview. Up and Down choose, Enter does it, Escape folds it. Below the search, the Name and the Text of the selection are edited in place, with duplicate, wrap, delete and run; the first problem is one click away.

Driving it from a script

The designer can run without a window, which is how its tests work:

raven_designer --null --frames 2 --script "open /tmp/ui f 2 search add~button expect <Button search wrap~in~a~vbox device 1 language fr do file.save"
raven_designer --null --frames 2 --script "open /tmp/ui f 2 dropon Slider 0/0 after moveto 0/0 0/1 after do view.run tab theme"
raven_designer --null --frames 2 --script "open /tmp/ui f 2 do view.interact clickin scroll 0 -40 pinch 1.5 swipe 200 3"
raven_designer --null --frames 1 --script "open /tmp/ui fuzz 3000 42"

The commands are listed at the top of designer_script in tools/designer/main.c; scroll DX DY, pinch SCALE and swipe DX FINGERS play a trackpad where the pointer is; fuzz STEPS SEED clicks, drags, types and plays the gestures of a trackpad at random (the same seed replays the same run), to look for crashes under a sanitizer.

29. What Raven does not do yet

  • Wayland: placing windows, keeping one above the others and fading a whole window (the protocol does not let an application do it); input methods (text-input-v3) for Chinese, Japanese and Korean.
  • Full OpenType shaping of complex scripts (Indic scripts, kerning); Arabic joining is done. The placement of the window of an input method.
  • In the text editor: several cursors, search and replace, folding, a language server client.
  • Dragging from a Raven window to another application. Glass over a native child window.
  • Mipmaps, a sub-allocator of GPU memory, recovery from a lost Vulkan device.
  • Node graph: knots, groups and comments, a minimap, undo (the application holds the model and its history). Timeline: nested tracks, curves between keys. Markdown: HTML, footnotes.
