XML reference

A window, or any part of one, can be written in XML. The XML only builds the tree of widgets: once loaded, every element is an ordinary widget, found with Rwidget_find and driven with the C API. Everything the XML says can also be said from C, and the other way round.

This page lists 44 tags of the library, 194 attributes of their own, and 102 attributes every widget can take. The tables come from the library itself (Rxml_get_attribute_info), so they are exactly what the loader understands.

1. Loading a document

Rid window = Rwindow_create_from_xml_file("editor.xml");        /* the root is <Window> */
Rid panel  = Rwidget_create_from_xml(text, strlen(text));       /* any widget as the root */
Rid other  = Rwindow_create_from_xml(text, strlen(text));       /* a <Window> given as text */

Rid save = Rwidget_find(window, "save");                        /* Name="save" */
Rbutton_set_text(save, "Save all");
Rwidget_set_attribute(save, "Style", "Primary");                /* any attribute, as text */

A document read from a file is watched: when it is saved, the window follows (see Files that are loaded again). A text given from memory is not. Paths written in a document given as text are relative to Rxml_set_base_path.

A complete small window:

<Window Title="Tool" Width="800" Height="500">
    <Shortcut Keys="Ctrl+S" Action="file.save"/>
    <VBox Spacing="8" Slot.Padding="12">
        <Label TextSize="18">Settings</Label>
        <HBox Spacing="8">
            <TextInput Name="path" Placeholder="Folder..." Slot.Fill="1"/>
            <Button Text="Save" Style="Primary" OnClicked="file.save"/>
        </HBox>
        <ListView Name="files" Slot.Fill="1"/>
    </VBox>
</Window>

2. Rules of the syntax

  • Tags are widget types; attributes are their properties. Names of tags and attributes are not case sensitive.
  • Elements, attributes, text, comments, CDATA, the five entities (&amp; &lt; &gt; &quot; &apos;) and numeric character references are understood. Files are UTF-8. There is no DTD and no namespace.
  • Inside an attribute, < and & are written &lt; and &amp;: If="{Count &lt; 3}".
  • The text inside an element is its Text attribute: <Label>Hello</Label> is <Label Text="Hello"/>.
  • Children are created first, then the attributes of their parent are applied, so Selected="1" or ActiveTab="2" can refer to children.
  • An unknown tag or attribute, or a wrong value, is reported through the error callback (R_ERROR_XML, with its line and column) and loading goes on.
  • Paths (Source, Font, Background...) are relative to the file, and a file is loaded once and shared by every widget that names it.
  • Lengths are logical units: they are multiplied by the scale of the monitor.

4. Actions

A widget has one action, the name of what its main event does. Action, OnClicked, OnChanged, OnCommitted and OnActivated are five spellings of it, kept for readability.

WidgetThe action fires when
Button, MenuItemit is clicked
Checkbox, Slider, SpinBox, ComboBox, TabView, Expander, ColorPicker, Timeline, NodeGraphits value changes
TextInputEnter is pressed
ListView, TreeView, TileViewa row is activated (double click or Enter)
static void on_save(Rid sender, const char* action, void* user_data) {
    /* sender: the widget, action: "file.save" */
}

Raction_bind("file.save", on_save, NULL);
Raction_set_default_handler(on_any_action, NULL);   /* everything that has no binding of its own */
Raction_fire("file.save", R_INVALID_ID);            /* as if a widget had fired it */

The typed callbacks of the C API (Rbutton_set_clicked_callback, Rtext_input_set_changed_callback for every keystroke, Rlist_view_set_selection_changed_callback...) work beside actions and cover the other events.

5. Attributes every widget has

Every tag below also takes these. The slot attributes are read by the parent: each panel uses those that make sense for it (a VBox reads Slot.Fill and Slot.HAlign, a Grid reads Slot.Column...). The color and metric attributes override the theme for the widget and what it contains; with a glass theme, the alpha of a color is the strength of the tint of the glass (Color.Control="#FF375F60" is a pink glass button).

6. Windows and their shell

<Window> is only a root, read by Rwindow_create_from_xml_file and Rwindow_create_from_xml. It holds one widget, its content; optionally an <Island> that floats at its top; any number of <Shortcut> and <Widget> declarations.

<Window Title="Tool" Width="1100" Height="720" CustomHeader="true" Theme="GlassDark">
    <Shortcut Keys="Ctrl+S" Action="file.save"/>
    <Island>
        <Label Text="Ready"/>                                <!-- folded   -->
        <VBox Spacing="6" Slot.Padding="12">                 <!-- unfolded -->
            <Label Text="Build finished"/>
            <Button Text="Run" OnClicked="run"/>
        </VBox>
    </Island>
    <VBox>
        <HeaderBar>
            <MenuBar>
                <Menu Text="File">
                    <MenuItem Text="Open..." Shortcut="Ctrl+O" OnClicked="file.open"/>
                    <Separator/>
                    <MenuItem Text="Quit" Shortcut="Ctrl+Q" OnClicked="app.quit"/>
                </Menu>
            </MenuBar>
            <Button Text="Run" Style="Primary" Slot.HAlign="Right" OnClicked="run"/>
        </HeaderBar>
        <DockArea Slot.Fill="1">
            <TextEditor Name="code" Slot.Title="main.c" Language="C" LineNumbers="true"/>
            <TreeView Name="files" Slot.Title="Files" Slot.Dock="Left" Slot.DockSize="0.22"/>
            <TextEditor Name="log" Slot.Title="Output" Slot.Dock="Bottom" Slot.DockSize="0.3" ReadOnly="true"/>
        </DockArea>
    </VBox>
</Window>

A MenuItem with a Shortcut works without a <Shortcut> element: the window looks in its menus when keys are pressed. In a window with CustomHeader, the HeaderBar draws the title and the window buttons; dragging it moves the window, and any widget with WindowDrag="true" does the same.

7. Panels

Panels place their children; how each child is placed is written on the child, in its slot (slot attributes).

<Grid Columns="auto,1" Rows="auto,auto,1" Spacing="8">
    <Label Text="Name"/>          <TextInput Slot.Column="1"/>
    <Label Text="Notes" Slot.Row="1"/>
    <TextEditor Slot.Row="1" Slot.Column="1" Slot.RowSpan="2" Height="120"/>
</Grid>

<Canvas>
    <!-- pinned to the bottom right corner, 16 units from it -->
    <Button Text="Help" Slot.Anchors="1,1" Slot.Alignment="1,1" Slot.Position="-16,-16"/>
    <!-- stretched over the whole width, 40 high -->
    <Border Background="#202020" Slot.Anchors="0,0,1,0" Slot.Size="0,40"/>
</Canvas>

<Splitter MinPaneSize="120">
    <TreeView Slot.Fill="1"/>
    <TextEditor Slot.Fill="3"/>

<Border Padding="16" CornerRadius="14" Shadow="24,0,8" Material="FrostedGlass">

13. Declaring tags

A document can declare its own tags. A <Widget> names a piece of interface, with parameters, and is then used like any tag of the library:

<Widget Name="Field" Label="Name" Hint="" Wide="false">
    <HBox Spacing="8">
        <Label Text="{Label}:" Width="{Wide ? 140 : 90}"/>
        <TextInput Placeholder="{Hint}" Slot.Fill="1"/>
        <Children/>
    </HBox>
</Widget>

<Field Label="Email" Hint="you@example.com" Name="email"/>
<Field Label="Password" Wide="true"><Button Text="Show"/></Field>

<Widget Name="Card" Title="">
    <Border Class="card" Padding="14">
        <VBox Spacing="6">
            <Label Text="{Title}" TextSize="17" If="{!empty(Title)}"/>
            <Children/>
            <HBox Spacing="6"><Children Name="footer"/></HBox>
        </VBox>
    </Border>
</Widget>

<Card Title="Upload">
    <Label Text="Drop files here"/>
    <Button Text="Send" Into="footer"/>
</Card>

<Repeat Count="3" Var="i">
    <Checkbox Text="Option {i + 1}"/>
</Repeat>
<ForEach Items="Red|Green|Blue" Var="c" Index="n">
    <Button Text="{n}: {c}" OnClicked="color.{lower(c)}"/>
</ForEach>
<Include Source="parts/toolbar.xml"/>
  • The attributes of <Widget> other than Name are its parameters, with their default values. It contains exactly one element: what the tag stands for.
  • Inside it, {...} is computed and replaced by its value; {{ and }} write a brace.
  • Where the tag is used, the attributes that are parameters give their values; the others (Name, Slot.Fill, OnClicked, Material...) go to the element the tag stands for. The text inside the tag is its Text.
  • <Children/> is replaced by the children given where the tag is used; <Children Name="footer"/> by those marked Into="footer".
  • A declaration is known from the moment it is read until the library shuts down, in every document loaded afterwards. Declaring a name again replaces it. It cannot take the name of a tag of the library, and it cannot use itself.
  • <Widgets> is the root of a file that only holds declarations. From C: Rxml_register_widgets, Rxml_register_widgets_from_file, Rxml_get_registered_widget_name.
Element or attribute
If="..."on any element: kept when the value is true
<If Test="...">keeps what it contains when the test is true
<Repeat Count="3" Var="i">repeats what it contains; {i} is 0, 1, 2
<ForEach Items="a|b" Var="x" Index="n" Separator="|">repeats for each text of a list
<Include Source="file.xml"/>brings in another file: its declarations, and its element if it has one

Expressions. Numbers, texts between single quotes, parameters and variables; + - * / % (+ joins texts), == != < <= > >=, && || !, a ? b : c, parentheses; min(a, b), max(a, b), round, floor, ceil, abs, len(text), upper, lower, empty(text), default(value, fallback); {Instance} is a number that differs for each use of a tag (for unique names). False is false, 0 and the empty text. {...} is only computed inside a <Widget>, a <Repeat> or a <ForEach>: elsewhere braces are ordinary characters.

14. Files that are loaded again

What is created from a file (Rwindow_create_from_xml_file, Rwidget_create_from_xml_file, the files they include, the files of Rxml_register_widgets_from_file, the theme files, the CSV tables) is watched while the application runs. Save the file in any editor and the interface follows:

  • an element still in the file keeps its widget: its handle, its callbacks, what was typed, scrolled or selected; only the attributes that changed are set again;
  • elements are matched by Name, else by content, else by position among those of the same tag; new ones are built, those that are gone are deleted;
  • a widget that manages its own content (ComboBox, Timeline, NodeGraph, menus...) is built again when what is inside it changes;
  • a file with a mistake changes nothing and the error is reported.
static void on_reload(const char* path, int ok, void* user) {
    if (ok) g_status = Rwidget_find(g_window, "status");   /* widgets built again have new handles */
}
Rxml_set_reload_callback(on_reload, NULL);
Rxml_set_live_reload(R_FALSE);       /* a shipped application; or RAVEN_LIVE_RELOAD=0 */
Rxml_check_files();                  /* look now (else five times a second) */

16. Documents, for tools

Rxml_document_parse reads a text into a tree of nodes that can be changed, written back with its comments (Rxml_document_to_string) and built (Rxml_document_create_widget, Rxml_document_create_window). A widget built from a document knows its node (Rwidget_get_xml_node), and a node its widget (Rxml_node_get_widget). Rxml_get_tag_count, Rxml_get_tag_name, Rxml_get_attribute_count and Rxml_get_attribute_info list the tags and their attributes: the tables of this page as data. The IDE is built on these functions.

RXmlError error;
Rid doc = Rxml_document_parse(text, strlen(text), &error);
if (doc == R_INVALID_ID) {
    printf("line %d, column %d: %s\n", error.line, error.column, error.message);
} else {
    Rid root = Rxml_document_get_root(doc);
    Rid button = Rxml_node_add_child(root, "Button", -1);      /* at the end */
    Rxml_node_set_attribute(button, "Text", "Added");
    Rid preview = Rxml_document_create_widget(doc);
    puts(Rxml_document_to_string(doc));
    Rxml_document_destroy(doc);                                /* what was built lives on */
}

/* every attribute of a tag, as the loader knows it */
int i, n = Rxml_get_attribute_count("Button");
for (i = 0; i < n; i++) {
    RXmlAttributeInfo info;
    Rxml_get_attribute_info("Button", i, &info);
    printf("%-20s %s\n", info.name, info.description);
}
