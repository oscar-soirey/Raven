Raven in other languages

Raven is a C library, so any language that can call C can use it. Raven comes with bindings for seven of them: C++, Python, Rust, Go, C#, Zig and LuaJIT. This page explains, for each one, how to install it, how the C API looks from that language, how callbacks and texts are handled, and what to watch for. The functions themselves are documented once, in the C API reference: every binding uses the same names.

Raven 0.2 packages (generated from the 0.1 API). The public API may still change before 1.0.

Every binding covers the whole of Raven.h: 500 functions, 39 enumerations, 14 structures and 33 kinds of callback, with the documentation comments of the headers. Three headers are left out everywhere, because they only make sense from C: raven_backend.h (writing a rendering backend), raven_vulkan.h (sharing the Vulkan device) and raven_web.h.

C#, Zig and LuaJIT are generated by the same script from the same data as the others but have no automatic test in the build: if something does not work the first time, please open an issue.

2. What every binding shares

Names

The C names are kept, so that the C API reference, the guide and the examples apply to every language. Two bindings rename, by a fixed rule:

CC++GoOthers
Rbutton_set_text(button, "OK")button.set_text("OK")raven.ButtonSetText(button, "OK")Rbutton_set_text
Rdraw_frame()raven::draw_frame()raven.DrawFrame()Rdraw_frame
R_WIDGET_BUTTONR_WIDGET_BUTTONraven.R_WIDGET_BUTTONR_WIDGET_BUTTON

Every object (window, widget, font, texture, timer, XML node) is a Rid, a 32-bit handle. R_INVALID_ID (0xFFFFFFFF) names nothing. A handle never owns what it names, in any language: a widget added to a parent is destroyed with it, and a widget never added is destroyed with Rwidget_destroy. Using a destroyed handle does not crash; it reports R_ERROR_INVALID_ID (see Errors).

The library

All the bindings but C++ load or link the shared library. The Python wheel and the NuGet package include it; for the others, take it from a release or build it:

cmake -B build -DRAVEN_BUILD_SHARED=ON
cmake --build build --config Release

This gives raven.dll and raven.lib on Windows, libraven.so on Linux and libraven.dylib on macOS. These environment variables tell the bindings where it is:

VariableRead by
RAVEN_LIBRARYPython, LuaJITthe path of the shared library
RAVEN_LIB_DIRRust (build.rs)the folder of the library, for the linker
RAVEN_STATIC=1Rustlink libraven.a / raven.lib instead
CGO_CFLAGS, CGO_LDFLAGSGo-I<raven>/include and -L<folder of the library>

At run time the program must also find the library: beside the executable on Windows, or on LD_LIBRARY_PATH / DYLD_LIBRARY_PATH. Raven draws with Vulkan: the machine needs a Vulkan driver (on macOS, MoltenVK); on Linux, libX11 is used for windows.

The UI thread

Raven belongs to the thread that calls Rinit. Call it from that thread only, except the functions documented as thread-safe (Rtask_post, Rwake_up). In Go this means runtime.LockOSThread() at the top of main; in C# and Python, do not call Raven from a Task or a threading.Thread. A call from the wrong thread reports R_ERROR_WRONG_THREAD.

XML and actions: the simplest way in every language

The binding code shrinks to almost nothing when the interface is described in XML. Name the widgets you need, name the actions they fire, and bind the actions:

<Window Title="Hello" Width="360" Height="200">
    <VBox Spacing="10" Slot.Padding="16">
        <Label Name="title" Text="Hello" TextSize="20"/>
        <TextInput Name="name" Placeholder="Your name"/>
        <HBox Spacing="8">
            <Button Text="Greet" Style="Primary" OnClicked="greet" Slot.Fill="1"/>
            <Button Text="Quit" OnClicked="quit"/>
        </HBox>
    </VBox>
</Window>

The program then does four things, in any language: Rinit, Rwindow_create_from_xml (or Rwindow_create_from_xml_file("main.xml")), Rwidget_find for each named widget, and Raction_bind for each action; then it loops on Rwait_frame(-1.0) and ends with Rshutdown. Actions are the one kind of callback every binding bridges, Go included, so an interface in XML needs no C callback at all.

When the XML is loaded from a file, save it while the program runs and the window follows, without restarting. The designer (raven_designer) edits that file, and its New project writes a starter program in each language. See the XML reference for every tag.

Errors

A function never throws or panics. A wrong handle, enumeration or value is reported to the error callback and the call returns a neutral value (0, R_INVALID_ID, an empty text). Install the callback first thing after Rinit while developing:

# Python
r.Rerror_set_callback(lambda code, severity, detail: print(r.Rerror_to_string(code), detail))

The other way is to ask: Rerror_get_last returns and clears the last error. Functions return R_TRUE (1) / R_FALSE (0) as integers, not booleans, in every binding but Python, where 0 and 1 are still falsy and truthy.

3. C++

Install

One header, bindings/cpp/raven.hpp, over the C headers. It needs C++11 and links like a C program, with the static or the shared library. From CMake, with an installed Raven or its sources:

find_package(raven REQUIRED)          # or add_subdirectory(Raven)
add_executable(app main.cpp)
target_include_directories(app PRIVATE ${RAVEN_ROOT}/bindings/cpp)   # or share/raven/bindings/cpp
target_link_libraries(app PRIVATE raven::raven)

Or by hand:

g++ -std=c++17 app.cpp -I<raven>/include -I<raven>/bindings/cpp -lraven

A program

#include <raven.hpp>
#include <string>

int main() {
    if (!raven::init(R_BACKEND_VULKAN)) return 1;

    auto window = raven::Window::create("Hello", 360, 200, R_WINDOW_DEFAULT);
    auto box    = raven::Panel(raven::Widget::create(R_WIDGET_VBOX));
    auto title  = raven::Label::create("Hello from C++");
    auto name   = raven::TextInput::create();
    auto greet  = raven::Button::create("Greet");

    box.set_spacing(10.0f);
    box.slot_set_padding(16.0f, 16.0f, 16.0f, 16.0f);
    name.set_placeholder("Your name");
    greet.set_style(R_BUTTON_PRIMARY);

    std::string greeting;
    greet.set_clicked_callback([&](Rid) {          // a lambda, captures included
        greeting = std::string("Hello, ") + name.get_text() + "!";
        title.set_text(greeting.c_str());
    });

    box.add_child(title);
    box.add_child(name);
    box.add_child(greet);
    window.set_content(box);

    raven::action_bind("quit", [](Rid, const char*) { raven::quit(0); });
    window.register_shortcut(R_KEY_ESCAPE, 0, "quit");

    while (raven::wait_frame(-1.0)) {}
    raven::shutdown();
}

From XML, the same thing is shorter:

const char xml[] = R"(<Window Title="Hi"><Button Text="Quit" OnClicked="quit"/></Window>)";
auto window = raven::Window::create_from_xml(xml, sizeof xml - 1);
raven::action_bind("quit", [](Rid, const char*) { raven::quit(0); });
// or: raven::Window::create_from_xml_file("main.xml")

How the C API looks

Classes
One class per kind of handle: Window, Widget and its kinds (Label, Button, Checkbox, Slider, TextInput, ComboBox, ListView, TreeView, Panel, Grid, Border, ScrollBox, Splitter, TabView, TextEditor, HeaderBar, DockArea, FileBrowser, Viewport, Custom...), TreeItem, Font, Texture, Timer, XmlDocument, XmlNode. The member functions are the C functions of that object without their prefix; Widget holds what every widget has.
Handles, not owners
A class is the size of a Rid, converts to and from it, and is false when it names nothing. Copying it copies the handle. It does not destroy anything when it goes out of scope: call destroy(), as in C. To view a handle as another kind, construct it: raven::Widget(button.get_parent()), raven::Panel(raven::Widget::create(R_WIDGET_VBOX)).
Callbacks
Every function that takes a callback has an overload that takes anything callable (std::function). The last C parameter, user_data, is dropped: capture what you need instead. The callable is kept until another one is set for the same object and event, or until the program ends. The C form (function pointer plus void*) is still there. raven::error_set_callback takes a plain function pointer, like the C function.
Free functions
Everything that is not a method is in the namespace raven: raven::init, raven::init_ex, raven::wait_frame, raven::action_fire, raven::xml_get_tag_count...
Texts
const char*, UTF-8. A text returned by Raven is valid until the next call that changes it: copy it into a std::string to keep it.
Drawing
raven::Painter wraps the RPainter* a paint callback receives: painter.rect(...), circle, line, curve, text, image, glass, spring...
auto canvas = raven::Custom(raven::Widget::create(R_WIDGET_CUSTOM));
canvas.set_paint_callback([](Rid, RPainter* p, float width, float height) {
    raven::Painter painter(p);
    painter.rect(0, 0, width, height, 8.0f, 0.10f, 0.12f, 0.16f, 1.0f);
    painter.text(R_INVALID_ID, 0, 12, 12, "Drawn in C++", 1, 1, 1, 1);
});

Because the C headers are included, any C function can also be called as it is, alongside the classes. The C++ wrapper is header-only; there is nothing to build.

4. Python

Install

pip install raven-gui

The package is named raven-gui (the name raven is taken on PyPI) and imported as raven. The wheels include the library, for Windows x64, Linux x86_64 (glibc 2.28 or newer) and macOS 11 or newer (Apple silicon and Intel). Python 3.7 or later, no dependency.

From the sources instead, copy bindings/python/raven.py and point it to a shared build:

RAVEN_LIBRARY=/path/to/libraven.so python3 app.py

The library is looked for in RAVEN_LIBRARY, then beside raven.py, then where the system looks; the error message lists every place that was tried.

A program

import raven as r

XML = """
<Window Title="Hello" Width="360" Height="200">
    <VBox Spacing="10" Slot.Padding="16">
        <Label Name="title" Text="Hello" TextSize="20"/>
        <TextInput Name="name" Placeholder="Your name"/>
        <Button Text="Greet" Style="Primary" OnClicked="greet"/>
    </VBox>
</Window>"""

if not r.Rinit(r.R_BACKEND_VULKAN):
    raise SystemExit("cannot start Raven")
r.Rerror_set_callback(lambda code, severity, detail: print("raven:", detail))

window = r.Rwindow_create_from_xml(XML)
title = r.Rwidget_find(window, "title")
name = r.Rwidget_find(window, "name")

def greet(sender, action, user_data):
    r.Rlabel_set_text(title, "Hello, %s!" % (r.Rtext_input_get_text(name) or "you"))

r.Raction_bind("greet", greet)

while r.Rwait_frame(-1.0):
    pass
r.Rshutdown()

How the C API looks

Names
Every C function, under its own name, in the module. Use import raven as r.
Texts
str on both sides, UTF-8 underneath. A function that may return NULL returns None. Byte buffers are bytes: r.Rfile_write("a.bin", b"..."), r.Rfile_read("a.bin").
Sizes
The size that follows a text or a buffer in C is not passed: r.Rwindow_create_from_xml(xml), not (xml, len(xml)).
Out-parameters
A parameter the C function writes through (int*, float*) is not passed: its value is returned, after the result of the function if it has one. x, y, w, h = r.Rwidget_get_rect(widget); width, height = r.Rwindow_get_size(window).
Structures
ctypes structures with the C field names, passed as they are (the binding takes their address). Fields that are texts in C are bytes.
desc = r.RInitDesc()
desc.backend = r.R_BACKEND_VULKAN
desc.app_name = b"My tool"
r.Rinit_ex(desc)

error = r.RXmlError()
if r.Rxml_document_parse("<A><B></A>", error) == r.R_INVALID_ID:
    print(error.line, error.column, error.message.decode())
Enumerations
enum.IntEnum (or IntFlag for flags) classes such as r.RWidgetType, and each member also at the top of the module: r.R_WIDGET_BUTTON. Values returned by Raven come back as members when they are one.
Callbacks
Any Python function, lambda or bound method, with the parameters of the C callback; user_data can be left out when you bind it and is then None. The binding keeps the function alive for as long as the library runs, so you need not hold a reference. Texts a callback receives are str; a callback that returns a text returns a str.
lst = r.Rwidget_create(r.R_WIDGET_LIST_VIEW)
r.Rlist_view_set_virtual_items(lst, 10000, lambda view, index, user: "row %d" % index)

r.Rtimer_create(0.5, r.R_TRUE, lambda timer, user: print("tick"))

An exception raised inside a callback cannot cross the C code: ctypes prints it and the call returns a default value. Catch what you need inside the callback.

Each call goes through ctypes, which costs about a microsecond. That is nothing for an interface driven by events, but a paint callback that draws thousands of shapes per frame is better written with fewer, larger calls, or in C.

5. Rust

Install

[dependencies]
raven-gui = "0.2"          # used as `raven`
# or, from the sources:
# raven = { package = "raven-gui", path = "<raven>/bindings/rust" }

The crate links the C library; it does not include it. Download the shared package of a release (or build it) and tell cargo where it is:

RAVEN_LIB_DIR=/path/to/raven/lib cargo run                # Linux, macOS
set RAVEN_LIB_DIR=C:\path\to\raven\lib && cargo run     # Windows: raven.lib; raven.dll beside the program

RAVEN_STATIC=1 links the static library instead; build.rs then adds the system libraries it needs (user32 gdi32 shell32 comdlg32 ole32 on Windows, X11 dl pthread m on Linux).

A program

use raven::*;
use std::cell::Cell;
use std::rc::Rc;

const XML: &str = r#"
<Window Title="Hello" Width="360" Height="200">
    <VBox Spacing="10" Slot.Padding="16">
        <Label Name="title" Text="Hello" TextSize="20"/>
        <TextInput Name="name" Placeholder="Your name"/>
        <Button Text="Greet" Style="Primary" OnClicked="greet"/>
    </VBox>
</Window>"#;

fn main() {
    unsafe {
        if Rinit(R_BACKEND_VULKAN) == 0 {
            eprintln!("cannot start Raven");
            return;
        }
    }
    let window = window_from_xml(XML);
    let title = widget_find(window, "title");
    let name = widget_find(window, "name");

    let clicks = Rc::new(Cell::new(0));
    let counter = clicks.clone();
    action_bind("greet", move |_sender, _action| unsafe {
        counter.set(counter.get() + 1);
        let who = text(Rtext_input_get_text(name));
        Rlabel_set_text(title, cstr(&format!("Hello, {}!", who)).as_ptr());
    });

    unsafe {
        while Rwait_frame(-1.0) != 0 {}
        Rshutdown();
    }
}

How the C API looks

raven::sys
The C API as it is: same names, raw pointers, #[repr(C)] structures, enumerations as integer constants, and every function unsafe. Everything in it is also at the root of the crate (use raven::*;).
Helpers
text(ptr) -> String reads a text of the library ("" for NULL); cstr(&str) -> CString makes one for it; action_bind(name, closure); window_from_xml, widget_from_xml and widget_find take &str. These are safe functions.
Texts
Pass cstr("...").as_ptr() directly as an argument: the temporary CString lives until the end of the statement, which is what the call needs. Do not store the pointer of a temporary in a variable. A zero inside the text ends it.
Out-parameters and structures
Pass &mut; zero a structure with std::mem::zeroed(), which is what C means by {0}.
unsafe {
    let (mut x, mut y, mut w, mut h) = (0.0f32, 0.0, 0.0, 0.0);
    Rwidget_get_rect(button, &mut x, &mut y, &mut w, &mut h);

    let mut desc: RInitDesc = std::mem::zeroed();
    desc.backend = R_BACKEND_NULL;
    desc.headless = 1;
    Rinit_ex(&desc);
}
Callbacks
action_bind takes any FnMut(Rid, &str) + 'static closure, kept until the program ends (use Rc<Cell> / Rc<RefCell> to share state with it). Every other callback is an unsafe extern "C" fn passed as Some(function), with a *mut c_void for your data, as in C:
use std::os::raw::c_void;

unsafe extern "C" fn on_click(button: Rid, user_data: *mut c_void) {
    let count = &mut *(user_data as *mut u32);
    *count += 1;
}

let count: &'static mut u32 = Box::leak(Box::new(0));
unsafe { Rbutton_set_clicked_callback(button, Some(on_click), count as *mut u32 as *mut c_void) };

A panic must not unwind through C: wrap the body of an extern "C" callback in std::panic::catch_unwind if it can panic. Raven is single-threaded on its UI thread and its handles are plain u32: nothing stops you from sending a Rid to another thread, so keep the calls on the thread that called Rinit.

6. Go

Install

Go has no registry: the package is used from the folder bindings/go (a module named raven) through a replace directive, which is what the projects of the designer do:

// go.mod of your program
module mytool

go 1.18

require raven v0.0.0
replace raven => /path/to/Raven/bindings/go
CGO_CFLAGS="-I<raven>/include" CGO_LDFLAGS="-L<folder of the library>" go run .

cgo needs a C compiler (gcc or clang; on Windows, MinGW-w64).

A program

package main

import (
    "fmt"
    "runtime"

    "raven/raven"
)

const xml = `
<Window Title="Hello" Width="360" Height="200">
    <VBox Spacing="10" Slot.Padding="16">
        <Label Name="title" Text="Hello" TextSize="20"/>
        <TextInput Name="name" Placeholder="Your name"/>
        <Button Text="Greet" Style="Primary" OnClicked="greet"/>
    </VBox>
</Window>`

func main() {
    runtime.LockOSThread() // Raven belongs to the thread that starts it
    if raven.Init(raven.R_BACKEND_VULKAN) == 0 {
        fmt.Println("cannot start Raven")
        return
    }
    raven.ErrorSetCallback(func(code raven.RError, severity raven.RSeverity, detail string) {
        fmt.Println("raven:", detail)
    })

    window := raven.WindowCreateFromXml(xml)
    title := raven.WidgetFind(window, "title")
    name := raven.WidgetFind(window, "name")
    raven.ActionBind("greet", func(sender raven.ID, action string) {
        raven.LabelSetText(title, "Hello, "+raven.TextInputGetText(name)+"!")
    })

    for raven.WaitFrame(-1.0) != 0 {
    }
    raven.Shutdown()
}

How the C API looks

Names
The prefix R is dropped and the rest is written in Go style: Rwindow_set_title is WindowSetTitle, Rtext_input_get_text is TextInputGetText. Enumerations keep their C names (raven.R_WIDGET_BUTTON), with Go types (raven.RWidgetType). A handle is a raven.ID.
Texts and buffers
string and []byte; the size that follows them in C is not passed. An empty string is passed as an empty text, never as NULL: where NULL has a meaning in C there is a function of its own (XmlNodeRemoveAttribute).
Out-parameters
Results: x, y, w, h := raven.WidgetGetRect(widget), w, h := raven.WindowGetSize(window).
Integers, not booleans
Functions return what C returns: raven.WaitFrame(-1.0) != 0, raven.IsRunning() == 0.
Callbacks
Three are bridged to Go functions, which is what an interface in XML needs: ActionBind, ErrorSetCallback (nil removes it) and TimerStart / TimerStop.
ticks := 0
timer := raven.TimerStart(0.5, true, func() { ticks++ })
// ...
raven.TimerStop(timer)
Written by hand for Go
A few functions that take structures in C have a simpler Go form: InitHeadless() (the null backend, for tests), XmlDocumentParse(xml) (document, line, column, message), FileRead(path) []byte, FileDialogOpen(parent, title) string.
Not wrapped
The functions that take a pointer to a structure, a void* or a C callback are left to cgo; they are listed at the end of raven.go. They include the per-widget callbacks (Rbutton_set_clicked_callback, Rslider_set_changed_callback...), Rinit_ex, the painter (Rdraw_*), textures from pixels and Rtask_*. Use actions instead of per-widget callbacks (OnClicked, OnChanged in XML, or WidgetSetAction), or call them through cgo with an //export function, as callbacks.go does.

7. C#

Install

dotnet add package Raven.Gui

The package holds the bindings (Raven.dll, .NET Standard 2.0) and the native library for Windows x64, Linux x64 and macOS (Apple silicon and Intel), which the .NET SDK copies beside the program. It runs on .NET 5 and later, .NET Core 3 and .NET Framework 4.7.2. Without the package, add bindings/csharp/Raven.cs to the project (it needs <AllowUnsafeBlocks>true</AllowUnsafeBlocks>) and put the library beside the program.

A program

using System;
using Raven;

static class Program
{
    const string Xml = @"
<Window Title=""Hello"" Width=""360"" Height=""200"">
    <VBox Spacing=""10"" Slot.Padding=""16"">
        <Label Name=""title"" Text=""Hello"" TextSize=""20""/>
        <TextInput Name=""name"" Placeholder=""Your name""/>
        <Button Text=""Greet"" Style=""Primary"" OnClicked=""greet""/>
    </VBox>
</Window>";

    static void Main()
    {
        if (R.Rinit(RBackend.R_BACKEND_VULKAN) == 0) { Console.WriteLine("cannot start Raven"); return; }
        R.Rerror_set_callback(R.Keep<RErrorCallback>((code, severity, detail) =>
            Console.WriteLine("raven: " + R.Text(detail))));

        uint window = R.Rwindow_create_from_xml(Xml);
        uint title = R.Rwidget_find(window, "title");
        uint name = R.Rwidget_find(window, "name");

        R.Raction_bind("greet", R.Keep<RActionCallback>((sender, action, user) =>
            R.Rlabel_set_text(title, "Hello, " + R.Rtext_input_get_text(name) + "!")), IntPtr.Zero);

        while (R.Rwait_frame(-1.0) != 0) { }
        R.Rshutdown();
    }
}

How the C API looks

Names
Every function is a static method of Raven.R, under its C name. Enumerations are C# enums (RBackend.R_BACKEND_VULKAN, RWidgetType.R_WIDGET_BUTTON), [Flags] where they are flags. A handle is a uint.
Texts
string in and out, UTF-8 underneath. The size that follows a text has an overload without it: R.Rwindow_create_from_xml(xml).
Out-parameters and structures
A parameter the C function writes through is an out; a structure is passed by ref. Where C accepts NULL, a second overload takes an IntPtr, for IntPtr.Zero.
R.Rwidget_get_rect(button, out float x, out float y, out float w, out float h);

var desc = new RInitDesc { backend = RBackend.R_BACKEND_VULKAN, app_name = R.Alloc("My tool") };
R.Rinit_ex(ref desc);
Pointers inside structures
Texts and pointers in a structure are IntPtr: R.Text(ptr) reads one; R.Alloc(string) makes one that lives until the program ends.
Callbacks
A delegate of the type of the C callback (RActionCallback, RTimerCallback, RPaintCallback...). The library keeps its address, not the delegate: wrap it in R.Keep(...) (or keep a reference in a field) or the garbage collector frees it and the next call crashes. Texts received by a callback are IntPtr: read them with R.Text. user_data is an IntPtr; with lambdas, capture instead and pass IntPtr.Zero.
R.Raction_bind("open", R.Keep<RActionCallback>((sender, action, user) =>
{
    string name = R.Text(action);   // "open"
    OpenDocument();
}), IntPtr.Zero);

An exception thrown in a callback must not cross into C: catch it inside. Keep every call on the thread that called Rinit (not from Task.Run or async continuations on the thread pool).

8. Zig

Install

Copy bindings/zig/raven.zig into the project (or take it from a release), and link the library in build.zig:

exe.linkSystemLibrary("raven");
exe.linkLibC();
exe.addLibraryPath(b.path("third_party/raven/lib"));   // where raven.lib / libraven.so is

Zig can also read the C header itself, with no binding file: const r = @cImport(@cInclude("Raven.h"));. raven.zig adds the documentation comments, typed callbacks and structures whose fields default to zero.

A program

const std = @import("std");
const r = @import("raven.zig");

var title: r.Rid = r.R_INVALID_ID;
var name: r.Rid = r.R_INVALID_ID;

pub fn main() void {
    if (r.Rinit(r.R_BACKEND_VULKAN) == 0) return;
    const xml =
        \\<Window Title="Hello" Width="360" Height="200">
        \\    <VBox Spacing="10" Slot.Padding="16">
        \\        <Label Name="title" Text="Hello" TextSize="20"/>
        \\        <TextInput Name="name" Placeholder="Your name"/>
        \\        <Button Text="Greet" Style="Primary" OnClicked="greet"/>
        \\    </VBox>
        \\</Window>
    ;
    const window = r.Rwindow_create_from_xml(xml, xml.len);
    title = r.Rwidget_find(window, "title");
    name = r.Rwidget_find(window, "name");
    r.Raction_bind("greet", greet, null);
    while (r.Rwait_frame(-1.0) != 0) {}
    r.Rshutdown();
}

fn greet(sender: r.Rid, action: ?[*:0]const u8, user_data: ?*anyopaque) callconv(.C) void {
    _ = sender; _ = action; _ = user_data;
    const who = std.mem.span(r.Rtext_input_get_text(name) orelse "");
    var buffer: [256]u8 = undefined;
    const text = std.fmt.bufPrintZ(&buffer, "Hello, {s}!", .{who}) catch return;
    r.Rlabel_set_text(title, text.ptr);
}

How the C API looks

Declarations
The C API as it is: pub extern fn with the C names, Rid = u32, enumerations as c_int types with constants (r.R_WIDGET_BUTTON).
Texts
?[*:0]const u8: a string literal passes as it is. A text returned by Raven is optional (NULL is null): std.mem.span(t orelse "") makes a slice of it. Texts you build need a terminating zero (bufPrintZ, allocator.dupeZ).
Structures
extern structs whose fields default to zero, so r.RInitDesc{} is the zeroed structure of C and .{ .backend = r.R_BACKEND_NULL, .headless = 1 } sets only what you need.
Out-parameters
Optional pointers: var x: f32 = 0; ... r.Rwidget_get_rect(w, &x, &y, &width, &height); (or null for what you do not need).
Callbacks
Functions declared callconv(.C) with the parameters of the C type (r.RActionCallback and the others are declared in raven.zig). Recent Zig versions spell it callconv(.c). Pass state through user_data or use container-level variables.
Memory
What Raven allocates for you (Rfile_read) is released with r.Rmemory_free, never with a Zig allocator.

9. LuaJIT

Install

luarocks install raven-gui

The rock installs the module raven. It needs LuaJIT (the binding uses its FFI; plain Lua 5.x cannot load it) and the shared library from a release: put it where the system finds libraries, or set RAVEN_LIBRARY to its path. Without LuaRocks, copy bindings/luajit/raven.lua next to the program.

A program

local r = require("raven")
local ffi = r.ffi

assert(r.Rinit(r.R_BACKEND_VULKAN) ~= 0, "cannot start Raven")

local xml = [[
<Window Title="Hello" Width="360" Height="200">
    <VBox Spacing="10" Slot.Padding="16">
        <Label Name="title" Text="Hello" TextSize="20"/>
        <TextInput Name="name" Placeholder="Your name"/>
        <Button Text="Greet" Style="Primary" OnClicked="greet"/>
    </VBox>
</Window>]]
local window = r.Rwindow_create_from_xml(xml, #xml)
local title = r.Rwidget_find(window, "title")
local name = r.Rwidget_find(window, "name")

-- keep the callback in a variable that lives as long as the program
local greet = ffi.cast("RActionCallback", function(sender, action, user_data)
    local who = ffi.string(r.Rtext_input_get_text(name))
    r.Rlabel_set_text(title, "Hello, " .. who .. "!")
end)
r.Raction_bind("greet", greet, nil)

while r.Rwait_frame(-1.0) ~= 0 do end
r.Rshutdown()
greet:free()

How the C API looks

The module
The C declarations of the headers given to ffi.cdef; the module is the library itself, so r.Rwidget_find is the C function. r.ffi is the FFI and r.C the loaded library.
Numbers and enumerations
Enumerations are numbers (r.R_WIDGET_BUTTON). Where a parameter has the type of an enumeration, its name as a string works too: r.Rwidget_create("R_WIDGET_VBOX"). R_TRUE / R_FALSE are 1 and 0, and 0 is true in Lua: always compare, if r.Ris_running() ~= 0 then.
Texts
A Lua string passes where C takes const char*. A text returned by Raven is a const char* cdata: ffi.string(ptr) makes a Lua string of it (check for NULL first when the function may return it: ptr ~= nil and ffi.string(ptr)). Sizes are passed explicitly: (xml, #xml).
Out-parameters and structures
Allocate them with the FFI:
local rect = ffi.new("float[4]")
r.Rwidget_get_rect(button, rect, rect + 1, rect + 2, rect + 3)
print(rect[0], rect[1], rect[2], rect[3])

local desc = ffi.new("RInitDesc")            -- zeroed
desc.backend = r.R_BACKEND_NULL
desc.headless = 1
r.Rinit_ex(desc)
Callbacks
A Lua function passes where a callback is expected, but a callback made implicitly is freed by the garbage collector. Make it with ffi.cast("RActionCallback", fn) (or the type of that callback), keep the result referenced while Raven may call it, and :free() it when you are done. LuaJIT has a limited number of callback slots (a few hundred): prefer one action bound to a name over a callback per widget. Texts a callback receives are const char* cdata too.
Errors in callbacks
A Lua error raised inside a callback called from C cannot be caught by the Lua code around the C call: catch it in the callback with pcall.

11. Testing without a screen

Every binding can run Raven with the null backend and no window system, which is how the build checks them: each example, started with --test, builds its interface, clicks its own button by injecting mouse events, and checks the result.

# Python
desc = r.RInitDesc()
desc.backend = r.R_BACKEND_NULL
desc.headless = 1
r.Rinit_ex(desc)

window = r.Rwindow_create_from_xml(XML)
r.Rdraw_frame()                                   # one layout pass
x, y, w, h = r.Rwidget_get_rect(r.Rwidget_find(window, "greet"))
r.Rwindow_inject_mouse_move(window, x + w / 2, y + h / 2)
r.Rwindow_inject_mouse_button(window, r.R_MOUSE_LEFT, 1)
r.Rwindow_inject_mouse_button(window, r.R_MOUSE_LEFT, 0)
assert r.Rlabel_get_text(title) == "Hello, you!"

In Go, raven.InitHeadless() does the first four lines. The examples (cpp/example.cpp, python/example.py, rust/examples/hello.rs, go/example/main.go) are complete tests to copy. With -DRAVEN_BUILD_TESTS=ON, ctest runs bindings_up_to_date and, where the tools are installed, binding_cpp, binding_python, binding_rust and binding_go (the last three need RAVEN_BUILD_SHARED, and are run by hand on Windows).

For maintainers: bindings\package.bat, from a Developer Command Prompt for Visual Studio, builds Raven (shared, Release) and writes the four packages into dist\bindings\ without publishing anything. --linux <folder> and --macos <folder> add the libraries of those platforms from the shared packages of a release; python bindings/set_version.py X.Y.Z changes the version everywhere (CMake, Cargo, NuGet, rockspec). The publishing commands are in bindings/PUBLISHING.md. A version can be published only once on each registry.

13. How the bindings are made

The bindings are not written by hand: tools/bindgen reads the public headers (cparse.py) and writes every file of bindings/, one generator per language (gen_<language>.py). That is why they always have the whole API, under the same names, with the same documentation. Do not edit the generated files; after changing a public header, run

python3 tools/bindgen/bindgen.py

The test bindings_up_to_date fails when this was forgotten. To add a language, write tools/bindgen/gen_<language>.py with a generate(api) function that returns {path: text}, and add its name to the list in bindgen.py; cparse.py documents the data it receives. Contributions of new languages are welcome on GitHub.
